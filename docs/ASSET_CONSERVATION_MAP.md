# 资产守恒与结算边界

本文是 v0.4.1 的资产端点清单。除明确标注的发行/销毁事件外，业务操作必须保持货币、商品或证券各自守恒；价格变化不等于资产发行。

## 权威端点

| 资产 | 权威端点 |
| --- | --- |
| 货币 | 玩家可用/冻结账户、NPC 市场账户、央行储备、公司现金、银行准备金与客户子账、合同/融资/公司行动/基金/期货/保险托管账户 |
| 商品 | 玩家真实背包、玩家/公司 custody、公司 legacy inventory、NPC 库存、订单冻结库存 |
| 证券 | 玩家可用/冻结持仓、基金持仓、库存股、系统流动性、债券/票据/期货仓位 |

央行政策投放、管理员 `/finance give`、初始账户资金和公司生产输出是显式来源；手续费、生产消耗、破产无法覆盖的已确认损失是显式去向。它们必须有类型化记录，不能伪装成普通转账。

## 跨端点操作矩阵

| 操作 | 来源 → 去向 | 提交前检查 | 提交、回滚与幂等 |
| --- | --- | --- | --- |
| 玩家转账/市场成交 | 买方可用或冻结 → 卖方可用 | 正数、乘法无溢出、余额及收款容量、库存/持仓 | 服务层原子结算；失败不推进订单；成交记录是唯一成功凭据 |
| 商品挂单/撤单 | custody ⇄ 冻结库存；资金 ⇄ 冻结资金 | 商品、数量、价格、所有权 | 下单先冻结；撤单精确解冻；订单 UUID 防重复 |
| 仓库存入 | 背包 → 玩家/公司 custody | 终端身份、距离、权限、容量、物品无特殊 NBT、槽位快照 | 先规划并复核背包移除，再入 custody；入账失败恢复物品；玩家 UUID + operation key 幂等 |
| 仓库提取 | custody → 背包 | 同上并检查背包完整容量 | 先规划插入，再扣 custody；插入失败恢复 custody；允许从超容量/停用仓库安全取回 |
| NPC/公司采购合同 | NPC 账户或公司现金 → escrow → 玩家 | 发布额度、期限、商品、发行方资金；交付时检查真实物品、收款容量、escrow 精确余额 | 发布失败原路退回；交付失败恢复商品；到期只向发行方退款一次；合同 operation key + 状态幂等 |
| 公司生产 | 输入 custody/legacy + 公司现金 → 输出 custody + 运营成本去向 | 同日标记、风险状态、原料、输出容量、维护费 | 全批次提交；失败恢复材料和现金；设施 lastProcessedDay 防双产 |
| 公司融资/债券/贷款 | 投资者/银行 → 托管或公司；到期反向 | 额度含认购中债务、股本/金额上限、收款容量 | 合约状态机与独立 escrow；失败退款；利息与本金逐期记录 |
| 分红/清算 | 公司现金 → 股东/债权人 | 全部收款容量、登记日权重、可分配金额 | `BigInteger` 比例分配 + 确定性余数；任何预检失败不退市、不删除债权 |
| 回购/要约/重组 | 公司/买方 escrow ⇄ 股东股份或卖方库存 | 已通过授权、双方权限、资金/股份/库存全量预检 | 原子交割；失败保留可重试任务；取消原价/原成本退回；行动与授权 ID 幂等 |
| 银行/基金/期货/保险 | 钱包、准备金、子账和各产品托管之间 | 复式平衡、保证金/准备金、头寸及收款容量 | 使用账本批次或明确补偿；重启恢复同一 reference 不重复记账 |

## 审计结论

- 新仓库、合同和公司经营路径没有把普通 `deposit`/`addCommodity` 当成无来源奖励；测试覆盖失败补偿、重复请求、到期退款和重启恢复。
- `setBalance`/直接恢复方法只用于初始化、存档恢复和测试夹具；管理员发行有独立权限与交易类型。
- 仓库方块的所有移除方式现在都会把物理端点设为 `DISABLED`，但不会删除 custody，管理员或玩家仍可按恢复流程取回。
- 后续新增跨端点操作必须先更新本表，并至少添加“失败不移动任一侧”和“重复调用不二次支付”测试。
