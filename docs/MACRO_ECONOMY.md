# 宏观实体经济（维多利亚 3 式）

目标：让金融层（银行、债券、央行、股票）下面有一层**会自己运转的实体经济**。玩家只是其中一股力量，
每个决定都会沿因果链传出去：

```text
央行利率 → 贷款/债券成本 → 公司扩张与雇工 → 工资流入聚落 → 人口消费与生活水平
   ↑                                                              ↓
 CPI（消费篮子价格） ← 聚落本地价格（供需） ← 商品供给（公司/摊位/商队） ← 需求（人口篮子）
                                        ↓
                         利益集团的满意度与影响力 → 法律 → 回到工资、关税、福利
```

全部模块在 `finance.macro` 包，模块熔断键 `MACRO_ECONOMY`，存档根 `MacroEconomy`，DataVersion 38 → 39，网络协议 16 → 17。

## 设计约束

- 人口只是数字，不生成、不扫描、不读取村民实体；全部计算放在日结里批量完成，每个聚落 O(商品数)。
- 资金守恒：所有新增资金流都走真实账户并留下类型化流水（见“资金流”）。不新增凭空印钱的入口。
- 商队到货进入聚落托管，而聚落托管只能被人口消费掉，玩家取不出来，所以不会刷出可提取的物品。
- 所有上限都有服务端配置与硬上限；存档里的坏记录单条隔离，模块降为只读，不影响其他模块加载。
- 配置 `macroEconomy.enabled=false` 时完全回到旧行为：村庄篮子、覆盖率溢价、商队定价、价格指数全部按原逻辑走。

## 第一步：聚落市场与人口

### 商品

在铁、小麦、石头之外新增 4 种默认商品（都有原版物品映射）：

| id | 物品 | 基准价 | 用途 |
| --- | --- | ---: | --- |
| `bread` | `minecraft:bread` | 20 | 食物（1 个面包 = 3 份食物需求） |
| `wood` | `minecraft:oak_log` | 4 | 住房、取暖 |
| `coal` | `minecraft:coal` | 6 | 取暖（1 块煤 = 2 份取暖需求） |
| `wool` | `minecraft:white_wool` | 9 | 衣物 |

### 需求类别与替代品

人口不再直接需要“小麦”，而是需要**类别**，每个类别可以由几种商品满足（`NeedCategory`）：

| 类别 | 权重 | 可选商品（每件折算的需求份数） |
| --- | ---: | --- |
| 食物 FOOD | 35 | 小麦 ×1、面包 ×3 |
| 住房 HOUSING | 15 | 石头 ×1、木头 ×1 |
| 工具 TOOLS | 15 | 铁锭 ×1 |
| 取暖 HEATING | 15 | 煤 ×2、木头 ×1 |
| 衣物 CLOTHING | 20 | 羊毛 ×1 |

每个职业有人均每日各类别份数（`MacroNeeds`）。食物、住房、工具三项与旧篮子的数量一致；
取暖和衣物是新增需求，一开始没有供给，新的生意机会就从这里来。
受雇工人（第二步）在自己的职业篮子之外，另有食物 +0.5、衣物 +0.3 的额外需求：有了收入就会多消费。

**替代分配**：某类别的需求按各商品“每份价格”的平方反比分摊，即 `share ∝ (本地价 / 折算份数)^-2`。
没有供给的商品（玩家摊位、聚落托管、NPC 库存都为 0）不参与分摊。如果所有候选都没有供给，就按基准价分摊，记为短缺。
分摊结果向下取整，余数给最便宜的那个商品；最便宜的一件装不下余数时（如 1.6 份取暖、煤一块 2 份），
按每份价格从低到高交给装得下的替代品，避免小聚落整类需求被取整成 0。

### 本地价格

每个聚落、每种商品都记一本日账（`LocalMarketBook`）：

- **需求** = 当天人口篮子换算出的商品数量 + 商队从这里出发的采购量（出口）。
- **供给** = 玩家摊位库存 + 聚落托管库存 + NPC 行商可供量（NPC 库存，上限为日需求 × 1.2）+ 当天商队到货（进口）。

维多利亚 3 式价格系数：

```text
gap    = (需求 − 供给) / max(1, min(需求, 供给))
target = 10000 × (1 + 0.75 × clamp(gap, −1, 1))      // 2500 .. 17500 基点
factor = 向 target 移动，每天最多 ±priceStepBps（默认 1000）
```

本地价 = NPC 中间价 × factor。启用后，`VillageService` 里村民的愿付价溢价改用这个系数（原来是库存覆盖率），
NPC 行商价也一样；所以短缺的聚落价格会高，过剩的聚落价格会低。每种商品保留最近 60 天的价格与供需历史。

### 生活水平（SoL）与人口

- 每天结算后，按“实际消费份数 / 当天下单份数”得出各类别满足率（某类别没有任何已注册的候选商品时，按原始需要份数计），
  加权后乘以 **4000**（`NEEDS_SOL_MAX`），再乘**饥荒系数** `0.5 + 0.5 × 食物满足率`。吃不饱时其他需求满足得再好也过不好。
- **自给加成**：`1000 × 自然规模 / 人口`，最多 3000。自然规模 = `villagePopulation`（新聚落的初始人口，默认 30）。
  人口等于自然规模、基本需求全满足、没有收入时，生活水平正好 5000（不涨不跌）；人口多了摊薄、少了变厚，所以没人管的聚落会回到自然规模。
- **收入加成**：人均日收入（工资 + 福利）每 1 元加 200，最多加 2000。默认工资 12 时每个岗位大约多养活 2.4 人，
  均衡人口 ≈ 自然规模 + 2.4 × 岗位数（见“平衡基线”）。
- `SoL` 每天向目标移动 1/5（平滑）。
- **增长**：日增长率 = `(SoL − 5000) / 5000 × growthMaxBps`（默认 150 = ±1.5%/天，实际 SoL 多在 4000..6500，即 ±0.5%/天以内）。小数部分累积到下一天，
  人口范围 [`minPopulation`, `maxPopulation`]（默认 5..400）。新增人口按默认职业占比分配，减少时按当前占比扣除。
- **迁移**：同一维度内，按“吸引力 = SoL（已含收入加成），骚乱时 −1000”排序；最低和最高的差距 ≥ `migrationGapBps`（默认 500）时，
  从最低的聚落迁往最高的聚落。每天应迁 `人口 × migrationMaxBps`（默认 0.5%）人：满 1 人时取整数部分，不足 1 人时每 ⌈1/x⌉ 天迁 1 人
  （无状态，小聚落不会因为“至少 1 人”被几天抽空）。每个维度每天最多迁移一对。
- `VillageRecord` 的人口与职业构成改为可变（`resize`），旧存档格式不变。

## 第二步：雇工、生产链与商队搬运

### 雇工

- 每个公司设施（`CompanyFacilityRecord`）的**劳动力来源** = 同一维度内最近的活跃聚落。
  - 所在维度一个聚落都没有：劳动力市场不存在，设施照常满员生产、不发工资（旧存档不受影响）。
  - 最近的聚落在 `laborRadius`（默认 256 格）以外：远距离通勤，产量再减半。
- 岗位数 = 设施等级 × `jobsPerLevel`（默认 10）。
- 公司日工资（每人每天）由所有者设定（`/macro wage <工资>`），默认 `defaultWage`（12）。
- **保留工资** = max(`baseReservationWage`（4），劳工法规定的最低工资)。工资低于保留工资时招不到人。
- 每天按工资从高到低分配劳动力，每个聚落可雇用的人数上限 = 人口 × 60%。员工变动：每天最多增减岗位数的 1/3，
  所以涨工资能慢慢挖人，降工资会慢慢流失工人。
- **发薪**：公司现金 → 聚落预算账户（`MACRO_WAGE` 流水），计入公司经营成本。现金不够时只保留付得起的人数。
- **产量**：`CompanyProductionService` 按 `在岗/岗位` 比例缩放投入和产出，全部向下取整；为 0 时设施状态记 `UNDERSTAFFED`。
  工会罢工时（第三步）产量再减半。传统自动经营（`LEGACY_AUTOMATIC`）的公司不受影响。

### 生产链

新增 4 个公司行业（`CompanyType`）：

| 行业 | 产出/天 | 投入/天 |
| --- | --- | --- |
| 食品加工 FOOD_PROCESSING | 面包 ×30 | 小麦 ×40 |
| 林业 FORESTRY | 木头 ×100 | — |
| 煤矿 COAL_MINING | 煤 ×80 | 铁锭 ×5 |
| 纺织 TEXTILE | 羊毛 ×40 | 小麦 ×10 |

投入沿用现有逻辑：设施模式从仓库取原料，传统模式从国际市场买。产出卖给 NPC 市场，NPC 行商再卖给聚落。
于是价格会连锁传导：小麦短缺 → 面包投入贵 → 面包贵 → 食物满足率下降 → 生活水平下降。

### 商队真的搬货

宏观经济开启时：

- 商队定价改用两端的**本地价格系数**，代替区域报价修正；套利空间就是两地真实的供需差。
- 发车时，采购量计入出发地的**需求**（出口），推高当地价格。
- 到货时，卖出的商品计入目的地的**供给**（进口），并放进目的地聚落托管供人口消费。资金流不变（仍由 NPC 市场收购）。
  于是短缺会被商队缓解，价差也会自然收敛。

## 第三步：CPI、利益集团与法律

### CPI 与宏观指标

- `CPI = Σ(各聚落篮子数量 × 本地价) / Σ(篮子数量 × 基准价) × 100`。
- 有聚落数据时，`EconomyMetricsService.calculatePriceIndex` 改用 CPI，央行 Taylor 规则的通胀缺口随之来自真实的生活成本，
  闭环就是：加息 → 贷款贵 → 扩张慢 → 供给少 → 物价 → 再调息。没有数据时保留旧的等权指数。
- 每天记一条宏观快照（最多 120 天）：CPI、总人口、平均 SoL、就业人数、工资总额、消费额。

### 利益集团

| 集团 | 影响力来源 | 关心 |
| --- | --- | --- |
| 乡村民众 RURAL_FOLK | 农民人口 | 生活水平、食物价格、福利 |
| 小资产阶级 PETITE_BOURGEOISIE | 工匠人口 | 生活水平、保护本地商人 |
| 军队 ARMED_FORCES | 守卫人口 | 工具（铁）供应 |
| 工会 TRADE_UNIONS | 受雇工人 | 工资相对保留工资、劳工权利 |
| 工业家 INDUSTRIALISTS | 公司设施产值 | 低劳动成本、自由贸易 |
| 金融家 FINANCIERS | 玩家与公司现金 | 通胀接近 2%、低福利支出 |

- **影响力**：人口集团 = 人数 × (0.5 + SoL)；资本集团 = √(价值 / `cloutValueScale`)（默认 100），
  钱越多影响力越大，但一个富玩家压不过全部人口。归一化成百分比。金融家的“价值”是私人现金，不含聚落预算账户。
- **满意度**（−10..+10）= 处境得分 + 现行法律立场 + 游说加成（每天衰减 1 点）。
- **不满后果**：工会满意度 ≤ −5 → 罢工，雇工产量减半；乡村民众或小资产阶级 ≤ −5 → 骚乱，人口增长减半、迁出吸引力 −1000。

### 法律

| 法律组 | 级别（默认 *） | 效果 |
| --- | --- | --- |
| 贸易政策 TRADE | 自由贸易 / 重商主义* / 保护主义 | NPC 行商价 ×0.9 / ×1.0 / ×1.25（保护主义利好玩家摊位，村民付更多，多付的部分作为关税进国库） |
| 劳工权利 LABOR | 无保护* / 最低工资 / 劳工保护 | 保留工资下限 = 最低工资；劳工保护再让雇工产量 ×0.9，并让 SoL 目标 +500 |
| 社会福利 WELFARE | 无* / 济贫法 / 公共卫生 | 国库每人每天拨给聚落 2 / 4 元，计入收入加成（+400 / +800 SoL）；见第四步 |
| 税制 TAXATION | 低税 / 中税* / 高税 | 公司利润税 5% / 15% / 30%；见第四步 |

- 任何玩家都可以 `/macro law propose <组> <级别>` 发起提案，费用 `lawProposalFee`（转入 NPC 资金池）；同一时间只有一个提案。
- 辩论期 `lawDebateDays`（默认 5 天）。期满时：支持度 = Σ 影响力 × 立场 × 满意度系数（0.5..1.5），
  反对度同理；支持度大于反对度就通过，否则失败。结果是确定性的，玩家能算得出来。
- `/macro lobby <集团> <金额>`：捐款转入 NPC 资金池，每 `lobbyPerPoint` 元换 +1 满意度（上限 +5，每天衰减 1）。

## 第四步：国家财政

前三步里，福利由 NPC 资金池凭空买单，贸易政策只改价格。这一步引入**国库**（系统账户 `Treasury.UUID`），让国家有真实的收入、支出和债务。
同一套法律、利益集团从此有了预算约束：要福利就得收税，收不上税就得借钱，借多了金融家不满、利息越滚越大。

### 收入

| 收入 | 来源 | 流水类型 |
| --- | --- | --- |
| 利润税 | 公司当日营业毛利（收入 − 成本，> 0 时）× 税率，在日利润结算前从公司现金扣缴，计入公司成本 | `MACRO_TAX` |
| 关税 | 保护主义下，村民向 NPC 行商多付的 25% 由 NPC 资金池转入国库 | `MACRO_TARIFF` |
| 提案费 | 法律提案费改为转入国库 | `MACRO_POLITICS` |

新法律组 **税制 TAXATION**：低税 5% / 中税 15%（默认）/ 高税 30%。

### 支出

| 支出 | 规则 | 流水类型 |
| --- | --- | --- |
| 行政开支 | 每人每天 `adminCostPerCapita`（默认 1），国库 → NPC 资金池（政府采购） | `MACRO_ADMIN` |
| 福利 | 济贫法 / 公共卫生的人均拨款改由国库支付 | `MACRO_WELFARE` |
| 债务利息 | 每天 `债务 × (基准利率 + 100 基点) / 年天数`，国库 → 央行 | `MACRO_DEBT_INTEREST` |

### 赤字与债务

- 每天发福利、付行政开支和利息之前，如果国库余额不够，就向**央行借款**补足缺口，债务上限 `debtCeiling`（默认 200,000）。
- 央行先用自己的准备金放款（玩家认购国债的钱就在这里）；准备金不够时才增发货币，并记 `MACRO_DEBT_ISSUANCE` 流水。所以长期赤字会推高货币量，进而推高 CPI。
- 到了债务上限还付不起的开支直接停发，并进入**紧缩**状态：福利不发，乡村民众和工会满意度 −2。
- 国库余额超过 7 天支出时，多出的部分自动还债（`MACRO_DEBT_REPAY`）。

### 和政治的衔接

| 集团 | 低税 | 中税 | 高税 |
| --- | ---: | ---: | ---: |
| 乡村民众 | −1 | 0 | +1 |
| 小资产阶级 | +1 | 0 | −1 |
| 工会 | −1 | 0 | +1 |
| 工业家 | +2 | 0 | −2 |
| 金融家 | +1 | 0 | −2 |

- 金融家的处境得分另按债务率扣分：债务超过上限的 50% 时 −1，超过 90% 时 −2。
- 紧缩期间乡村民众、工会各 −2。

### 财政基线

365 天长期模拟（默认法律：重商主义、中税、无福利）加入日利润结算和利润税后：国库全年保持小额结余（年末约 17,000），
从未借款、没有紧缩，货币守恒（含央行增发项）仍然成立，各公司全年仍然盈利。粗算：总人口约 165 时行政开支约 165/天；
若改成公共卫生（4 元/人/天，约 660/天），在中税下每天赤字约 600，大约一年碰到 20 万的债务上限，随后进入紧缩。
这正是想要的张力：福利要靠高税或借债来养。

### 命令与界面

- `/macro budget`：国库余额、债务、昨日各项收支、税制与紧缩状态。
- “宏观”页签顶部多一行国库摘要。

## 平衡基线

默认参数由一年期无头模拟调出：`finance.simulation.MacroLongRunSimulationService`，单测
`MacroLongRunSimulationServiceTest` 把下面的指标当作回归门槛。

### 场景

- 3 个聚落，同一维度、相距 1000 格：alpha 40 人、beta 30 人、gamma 20 人；自然规模 30。
- 5 家公司，各 1 个 1 级设施（10 个岗位）、初始现金 20,000、默认工资 12、自动卖出 95%：
  alpha 旁边是面包厂（食品加工）和林场，beta 旁边是煤矿和纺织厂，gamma 旁边是铁厂（原材料）。
- 原料每天按国际市场卖价从 NPC 买进仓库（代表玩家运货，钱转给 NPC 资金池）。
- 每天的顺序与 `EconomyCycleService.tickDay` 一致：`beforeVillages → VillageService → afterVillages → naturalConsumeAll →
  MacroLaborService → CompanyProductionService`，之后补 20 次国际市场动能衰减（一个 MC 日里的分钟 tick；不跑随机噪音，保证确定性）。
- **冲击**：第 150～240 天铁厂把工资降到 0（全员离职、停产），之后恢复默认工资。
- 同一场景跑两遍，结果逐项一致（确定性）。

### 结果（365 天）

| 指标 | 结果 | 门槛 |
| --- | --- | --- |
| 货币守恒 | 每天都满足：账户余额 + 公司现金 + 累计维护费（27,960）= 初始 52,100,000 | 必须成立 |
| 人口 alpha / beta / gamma | 40 → 64、30 → 64、20 → 37（第 1000 天：76 / 76 / 52，理论均衡 78 / 78 / 54） | 不碰 5 / 400，一年内不超过 200 |
| 冲击 | gamma 停工期间 33 → 29（SoL 降到 5000 左右，人口迁往 beta），复工后回升到 37 | 停工期间下降、复工后回升 |
| 生活水平 | 稳态 5200～5500；增长期最高约 6350 | — |
| 价格系数 | 全部在 8500～10000，没有一天卡在 2500 或 17500 | 连续卡边界 ≤ 30 天 |
| CPI | 第 1 天 88.0 → 第 60 天 79.9 → 第 365 天 80.0；第 120 天起年化 −0.4%，第 30 天起年化 −2.3% | 稳态 −3%～+5%，含磨合期 > −10% |
| 公司现金 | 面包厂 60,738、林场 81,158、煤矿 98,631、纺织厂 59,394、铁厂 245,180（全年最低都 ≥ 初始的一半） | 不低于初始一半，年末盈利 |

### 调整了什么、为什么

| 参数 | 原值 → 新值 | 原因 |
| --- | --- | --- |
| 基本需求满分 SoL（`NEEDS_SOL_MAX`） | 10000 → 4000 | NPC 行商什么都供得上，需求总是全满足，SoL 恒为 10000，人口一年 90 → 536 单调涨向上限 |
| 自给加成（`SUBSISTENCE_SOL`） | 无 → 1000 × 自然规模 / 人口（≤ 3000） | 只降需求分会让没有工作的聚落一路缩到下限；自给项给出“自然规模”这个稳定点 |
| 收入加成（`INCOME_SOL_PER_UNIT` / 上限） | 150 / 1500 → 200 / 2000 | 让工资决定均衡人口：每个岗位约养活 2.4 人 |
| `growthMaxBps` | 50 → 150 | SoL 的实际波动范围变窄后，原速度要好几年才收敛 |
| `migrationGapBps` / `migrationMaxBps` | 1500 / 1% → 500 / 0.5% | 新 SoL 范围里 1500 的差距几乎不会出现；原来“至少 1 人”让 22 人的聚落 20 天被抽空 |
| 福利（济贫法 / 公共卫生） | 5 / 10 → 2 / 4 元每人每天 | 福利按人头发、不随人口摊薄，原值（+750 / +1500 SoL）会让人口无上限增长；新值把均衡人口抬高约 1.7 / 5 倍 |
| 面包基准价 | 12 → 20 | 原价每份食物只值 4，比小麦（8）便宜一半，面包厂买小麦做面包必亏，约 90 天现金归零 |
| 食品加工投入 | 小麦 60 → 40 | 同上；现在每天毛利约 250，扣工资 120 后约 +110 |
| 纺织投入 | 小麦 20 → 10 | 原毛利只够发工资，现在约 +100/天 |

### 已知的结构性现象

- **NPC 行商的“供给”是需求的 1.2 倍**，所以由 NPC 供货的商品价格系数稳定在 8500 附近（轻微过剩），CPI 稳态约 85 而不是 100。
  这是有意保留的：玩家摊位要和一个有余量的 NPC 竞争，价格系数只有在 NPC 断货、出口或玩家大量供货时才会明显偏离。
- **开服头 ~60 天 CPI 从 88 落到 80**：本地价格系数从 10000 落到 8500，公司开始向国际市场卖货、NPC 库存略高于参考库存，
  中间价小幅回落；之后基本持平。
- 国际市场开服库存原来是 60,000，比参考库存 100,000 低，开服价格高出基准约 20%，头 ~120 天 CPI 会一路下跌约 14%，
  央行看到的是一段假通缩。现在开服库存等于参考库存，开服价格就是基准价（只影响新商品的初始库存，已有存档不变）。
- 村民从摊位和行商买货时回写国际市场动能，原来记成“国际市场买入”（利空），方向反了；现在记为需求（利多）。
- 铁厂（原材料，没有投入）的利润远高于新行业，这是旧行业的数值，本次没有动。

## 世界反馈

`MacroWorldFeedback` 只做表现，不改数值，可用配置 `macroEconomy.worldFeedback` 关闭。

- **聚落心情**（每 5 秒，只处理已加载且 24 格内有玩家的贸易站）：生活水平 ≥ 70% 冒开心粒子；挨饿（食物 < 50%）或骚乱冒愤怒粒子。
  附近玩家每分钟最多在动作栏听到一次村民抱怨——抱怨满足率最低（< 60%）的那一类（“晚上冷得睡不着，煤都去哪儿了？”），
  骚乱时喊着要上街，过得好时夸两句，并配村民的同意/拒绝音效。
- **工厂**：罢工时有工人的工厂冒篝火浓烟、村民摇头，每 15 秒在动作栏提示“工人在门口罢工”；缺人停产的工厂冒烟。
- **商队到货**：目的地贸易站放一枚烟花（盈利金色、亏损红色）并敲钟，在线的商队主人收到“卖出多少、本趟盈亏”的消息。
- **重大事件**交给《金融周报》（见下一节）：大事出号外或快讯，小事只上周报。
  开服后的第一次日结只记基线，不会把重启前就存在的状态再报一遍。

## 《金融周报》与商情调查

经济里发生的事不再每天刷聊天栏，而是交给报社：

- **新闻池**：罢工、骚乱、饥荒、法案、紧缩等事件按新闻价值打分进池（饥荒 90、罢工 80、紧缩 75、骚乱/法案通过 70、法案被否 50、结束类 35～40）。
- **周刊**：每 `newsIntervalDays`（默认 7）天出一期。头版是本周分数最高的事（没有就用涨跌最大的商品）；
  另有市场版（CPI 周变化、涨跌前三的本地价格）、民生与政坛版（各聚落人口与生活水平、最不满的集团、待表决提案、国库）、
  其他新闻、商机栏（一条免费但标注“调查于第 N 天”的旧情报）。
- **号外**：大事当天出号外，号外之间至少隔 `newsExtraGapDays`（默认 3）天；赶上冷却只在聊天栏发一句“快讯”，详情等周刊。
  号外发过的事仍留在池里，周刊会再回顾。小事（罢工结束、饥荒结束等）只上周报，不进聊天栏。
- **领取**：报纸是成书。出版时全服提示一句；到任意聚落贸易站右键或 `/macro news` 领取，每期每人一份，过刊保留最近 8 期。
  每份书末尾附“你的生意”：领报时生成的公司近一周利润、雇工与工资、商队盈亏，以及这一周里和你有关的新闻（如商队到货）。
- **商情调查** `/macro radar`：花 `radarCost`（默认 200，进国库）立即拿到当前最好的三个商机，冷却 `radarCooldownDays`（默认 1）天。
  四类：短缺（本地价格系数 ≥ 130% 且供不应求）、商路套利（每趟 64 件扣掉保镖工资后的利润）、廉价劳动力（≥ 10 人没工作）、
  政策风向（进行中的提案会影响什么）。情报带调查日期，价格会被商队和村民拉平，两三天后最好重查。

## 资金流

| 流 | 方向 | 流水类型 |
| --- | --- | --- |
| 工资 | 公司现金 → 聚落预算账户 | `MACRO_WAGE` |
| 福利 | 国库 → 聚落预算账户 | `MACRO_WELFARE` |
| 提案费 | 玩家 → 国库 | `MACRO_POLITICS` |
| 游说 | 玩家 → NPC 资金池 | `MACRO_POLITICS` |
| 利润税 / 关税 | 公司现金 → 国库 / NPC 资金池 → 国库 | `MACRO_TAX` / `MACRO_TARIFF` |
| 行政开支 | 国库 → NPC 资金池 | `MACRO_ADMIN` |
| 借款 / 还款 / 利息 | 央行 ⇄ 国库（准备金不足时央行增发，记 `MACRO_DEBT_ISSUANCE`） | `MACRO_DEBT_BORROW` / `MACRO_DEBT_REPAY` / `MACRO_DEBT_INTEREST` |

聚落预算账户本来就由 NPC 资金池补足（`VILLAGE_BUDGET_TOPUP`），工资进来后，资金池的补足会相应减少。
