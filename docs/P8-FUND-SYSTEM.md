# Phase 8 基金系统设计与审计

## 已实现范围

实现全市场股票指数基金、行业主题指数基金和货币/短债基金。ETF 二级市场、做市商、杠杆、反向、多币种、收益保证不在本阶段范围。

## 守恒边界

- 申购：玩家钱包减少 = 基金托管现金增加 + 明确转入费用账户的申购费；玩家份额与基金总份额同步增加。
- 赎回：付款成功后才同时扣减冻结份额和基金总份额。现金不足时请求保持 `PENDING`，玩家权益不会消失。
- 净值：现金 + 股票市值 + 债券市值 + 央行票据预计兑付值。缺价会标记降级并暂停新申购。
- 费用：申购费、赎回费和管理费进入央行系统账户，不做无去向销毁。
- 再平衡：股票通过 `StockMarketManager.placeLimitBuy/placeLimitSell`，央行票据通过 `CentralBankBillManager.subscribe`；不直接篡改市场库存。

## 存档与迁移

`DataVersion = 23`。基金定义、运行状态、净值历史、玩家份额、冻结份额、赎回请求、定投计划和幂等键均独立持久化。版本 13、15、17、19、20、21、22 直接升级测试会删除新标签模拟历史存档；旧存档只获得空份额的默认基金定义。

## 已知限制

- 股票再平衡依赖现有订单簿和做市商，可能部分成交；当前保存批次日期以避免同日重复触发，但没有独立的逐订单再平衡任务日志。
- 货币基金目前以现金和 7 日央行票据为主，企业短债自动筛选仍保留为后续增强。
- 基金页提供列表、申赎和定投入口；完整成分详情、净值折线和逐项收益归因尚未拆成独立大页面。
- 长期模拟会经过基金日周期与一致性检查，但尚未模拟大量玩家并发申赎和真实 Netty 丢包重发。
