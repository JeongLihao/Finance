# 区域商品经济与高级风险金融

本系统把聚落需求、实体仓储、商业银行、期货和保险连接到同一组权威资产端点。区域指标只提供信息与后续新需求的有界报价修正，不创建第二套现货市场。

## 权威资产流

```text
NPC 市场账户 → LocalDemand escrow → 完成交付的玩家账户
玩家背包 → 聚落 custody

公司 custody ──reservation──> 仍属公司但不可用的质押数量
银行复式总账 → 公司存款/贷款 → 公司现金
违约后：质押商品 → 协议清算 custody → NPC 实际买入 → 银行贷款回收

个人钱包 ↔ 个人保证金账户 ↔ 现有期货逐日盯市
公司 hedge objective ──只读关联──> 经营者真实期货仓位

投保人/银行 → 保险池；保险池 → 公司所有者或贷款银行
```

- 区域键为 `dimension + settlement UUID + commodity`。不向客户端发送仓库坐标、玩家身份、运输令牌或路线。
- `RegionalCommodityMetricsService` 只接受成功创建、完成或到期的真实聚落需求。日结生成最多 120 日历史；本地报价修正限制在 7500～14000 基点，单日最多变化 1000 基点。
- 调查板仍只保存 assignment UUID；选择目标时会优先考虑当前维度已登记且确有短缺历史的聚落，不扫描或加载新区块。

## 库存质押

- 只允许 PLAYER_DRIVEN/HYBRID 公司的真实 custody 商品。`InventoryCollateralManager` 的 reservation 是唯一冻结索引，生产、提取、销售、运输和重组最终都受 `CommodityInventoryManager.removeCommodity` 的可用量检查约束。
- 创建顺序固定为：估值与权限预检 → PENDING reservation → 真实商业银行贷款 → ACTIVE；贷款失败删除 PENDING reservation。
- 估值采用全局 NPC 中间价与 3000～7000 基点 haircut，使用 `BigInteger`。缺价拒绝新质押。
- 追保至少保留一个完整 MC 日。清算会把已冻结商品移动到协议 UUID custody，再调用 NPC 真实买入；卖不掉时保持 `LIQUIDATING`，不会删除商品或银行债权。
- 公司破产会先强制处置质押品并冲减担保贷款；未成交商品、未入账回收款或实体仓库未变现库存都会暂停公司删除，剩余无担保债权随后才进入普通清算池。
- 每日重估使用持久化轮转游标和有界批次。软上限、批次和 LTV 可在服务器配置中调整；降低软上限不删除既有协议。

## 公司经营对冲

首版安全实现不让 company UUID 冒充玩家保证金账户。`CompanyHedgeObjective` 只把公司真实采购/销售数量与创建者的个人期货仓位关联：

- `INPUT_COST` 只认可同商品多头；`OUTPUT_PRICE` 只认可同商品空头。
- 覆盖率按真实手数 × 合约乘数计算并限制 0～20000 基点。
- 创建目标不下单、不转钱、不产生盈亏；反向仓位覆盖率为零，超额仓位只警告。
- GUI 明示“个人保证金账户”，因此这些盈亏不进入公司财报。正式公司保证金端点留待能证明复式结算与清算守恒后再实现。

## 保险证据

- 仓储事故通过 `CompanyInventoryFacade` 原子扣减真实可用库存。已质押数量只记录在证据中，不能作为普通损失重复赔付；事件创建失败恢复原库存。
- 营业中断只读取设施连续 `statusSinceDay`、结构化停产原因和服务端财务历史。`DISABLED`（玩家主动关闭）不构成自动赔付证据。
- 运输货箱损毁仍保留 transport custody，因此不按商品全损赔付。
- 抵押贷款违约时，质押清算回收先冲减贷款。信用险等待清算终态，并从协议累计的审计回收额计算净损失，客户端不能提交 recovered。

## 数据、网络与恢复

- `DataVersion 36`：新增 `RegionalCommodity`、`InventoryCollateral` 和 `CompanyHedges` 独立区段；旧存档缺失时为空，不生成资产。
- 网络协议 `14`：区域风险响应最多 128 行，趋势最多 7 点，字符串和枚举均有边界。质押写操作要求有效银行柜台会话；对冲写操作要求高级证券界面。
- 损坏质押记录若仍能解析 custody、商品和数量，会转为 orphan reservation 并暂停质押模块，避免重启后静默解冻资产。
- 模块暂停时拒绝新增风险头寸；安全还款、可验证释放和只读诊断仍可继续。

## 已知边界

- 普通 NPC 现货成交尚未绑定到 settlement UUID，因此不会伪装成村庄交付；没有可靠区域归属的数据暂不写区域快照。
- 运输合同尚无真实延误罚金端点，所以未新增“货物全损”或“未实现利润”赔付。
- GUI 与自动化已做源码/协议测试；320×240、不同 GUI Scale、双客户端和真实旧世界连续重启仍需按 RC 人工清单在游戏进程中验证。
