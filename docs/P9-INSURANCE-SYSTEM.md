# Phase 9：企业风险保险

## 范围

本阶段实现三类保险：公司库存灾害险、公司营业中断险、商业银行公司贷款信用险。系统保险池是唯一承保主体；暂不引入玩家保险公司、再保险、保险证券化或可交易保单。

## 资金与状态

- 玩家公司的保费从玩家账户转入保险池。
- 贷款信用险保费从商业银行准备金支付，并记为银行保险费用。
- 普通理赔从保险池转给保单受益人；信用理赔进入银行准备金，同时等额冲减银行贷款资产和贷款合同本金。
- 保单购买后次日生效，避免已知事件发生后补买保险。
- 保险池不足时按批次部分赔付，未付部分保留为债权，不会静默删除。

## 可验证损失

- 库存灾害必须由服务器事件实际扣减公司库存，损失按事件时市场中间价核算。
- 营业中断要求至少三期利润历史、超过等待期，并以历史平均与实际收入差额核算。
- 信用险只接受商业银行贷款进入 `DEFAULTED` 后产生的未回收本金。
- 事件 ID 确定生成；同一保单和事件只能产生一张理赔。

## 运维与恢复

保险数据位于 `Insurance` NBT 分区，`DataVersion = 24`。管理员可以暂停/恢复保险模块并查看保险池现金、敞口和未付理赔。一致性检查会验证保单、事件与理赔引用、重复理赔、剩余限额和汇总值。旧存档升级时不创建玩家资产，系统保险池在首次保险周期或操作时初始化。

## GUI 与网络

金融页“保险”子页显示公司风险等级、库存保障、保单期限、剩余额度和理赔状态。网络响应限制为每类 128 行；字符串、期限、金额、权限和请求频率均在服务端校验。客户端不能直接创建损失事件。
