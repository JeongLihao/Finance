# Finance — Minecraft 服务器金融系统模组

Finance 为 Minecraft Forge 服务器加入一套虚拟经济、商品交易、公司经营、股票市场和中央银行调控系统，并扩展公司财报、融资增发、股东投票、分红、公司债券、贷款、信用评级、指数和破产退市等完整公司生命周期玩法。

- 版本：v0.4.1
- 平台：Minecraft 1.20.1 / Forge 47.4.16
- 作者：H-Jeong
- 更新日志：[CHANGELOG.md](CHANGELOG.md)

> README 只保留模组介绍、安装方式和游戏内操作说明；版本变化和修复记录请查看更新日志。

## 功能概览

### 专业行情详情

商品和股票共用服务端日 K 行情。进入商品或股票页、选择标的后点击“K线”，可选择最近 30、60 或 120 个 MC 日；详情页保持在 400×250 主窗口内，通过 `K+MA → MACD → RSI → Book → Trades → Ranks → VolRank` 循环按钮切换：

- `K+MA`：OHLCV 蜡烛、成交量、MA5 与 MA10；当天尚未收盘时会显示“进行中”。
- `MACD`：EMA12、EMA26、DIF、DEA9 与柱状差值。
- `RSI`：标准 Wilder RSI14，并标出 70/30 参考线。
- `Book`：商品或股票真实限价单聚合出的买卖五档，不发送完整订单簿和玩家 UUID。
- `Trades`：当前标的最近 20 笔成交，按新到旧显示 MC 日、时间、方向、价格和数量。
- `Ranks` / `VolRank`：商品与股票分别计算涨幅、跌幅、成交量和放量 Top 5。

行情按标的按需加载；快速切换标的或 30/60/120 日窗口时，迟到的旧响应不会覆盖当前图表。加载中、空历史和服务器响应较慢会显示不同状态。

价格提醒除固定目标价外，还支持“突破前一完整交易日最高价”和“跌破前一完整交易日最低价”。提醒基于服务端 K 线判定，触发一次后自动关闭。

当前版本的核心目标是让服务器经济从“单次买卖”升级为可持续运行的金融系统：商品价格会随供需和 NPC 市场变化，股票价格会参考公司基本面，中央银行会在市场失控时介入，公司则可以经历创建、经营、上市、融资、治理、分红、风险预警和退市清算。

### 指数基金与长期理财

金融页新增“基金”子页，提供全市场股票指数基金、原材料主题指数基金和货币/短债基金。基金不是复制指数点位：申购资金进入独立托管账户，股票基金通过现有股票订单接口获取真实持仓，货币基金持有现金与真实央行票据，净值由这些底层资产、利息和费用共同决定。

玩家可以输入金额申购、按万分之一份额精度赎回，或设置按 MC 日执行的定投计划。现金不足时赎回会保留为待处理债权并冻结相应份额，不会直接删除持仓；基金页会显示净值涨跌、费用、份额、冻结份额、近期波动和流动性提示。历史不足时风险指标明确显示“数据不足”。

### 账户系统

每个玩家都有独立银行账户，支持余额查询、转账、交易扣款、订单资金冻结和取消返还。新玩家首次加入会自动获得初始资金。

这里的“普通账户”是玩家钱包，不是商业银行存款。金融界面的“银行”分页提供系统商业银行：把钱包资金存入后，钱包减少、银行准备金资产与客户存款债权同时增加，不会把同一笔钱重复计算。玩家可以办理活期存取、锁定利率的定期存款和跨行支付；公司所有者还可申请商业银行贷款，并把公司银行存款提取到公司现金。

商业银行采用复式总账，持续核对“资产 = 负债 + 权益”。跨行支付会同步移动付款行和收款行的准备金；同行支付只调整客户明细，不虚构准备金流动。公司贷款会同时形成银行贷款资产和公司存款负债，利率由基准利率、公司信用、期限与银行利差组成。坏账计提贷款损失准备，资本或流动性不足会限制新增业务；流动性缺口先尝试同业隔夜拆借，再使用有总额和惩罚利率限制的央行最后贷款人安排。

存款保险按“同一客户、同一家银行、活期与定期合并”计算，默认保障上限为 100,000。进入处置的银行只把受保部分迁移到桥接银行，未受保部分仍留作原银行债权；同一银行不会重复赔付。普通玩家只会收到公开利率与风险指标，完整资产负债表和处置操作仅对管理员开放。

### 商品系统

模组默认注册三种基础商品：

| 商品 | 对应物品 | 分类 |
| --- | --- | --- |
| 铁锭 | `minecraft:iron_ingot` | 原材料 |
| 小麦 | `minecraft:wheat` | 食物 |
| 石头 | `minecraft:stone` | 建筑方块 |

管理员可以在 GUI 中添加更多 Minecraft 物品作为可交易商品。玩家拥有独立的虚拟商品库存，可以把背包物品存入商品库存，也可以从商品库存取回背包。

### 商品市场

Finance 包含两套商品市场：

- P2P 市场：玩家之间挂限价买单/卖单，价格匹配时自动撮合，支持部分成交和取消订单。
- 国际市场：系统做市商提供即时买卖报价，市场库存、成交动量、供需趋势和噪声共同影响价格。

市场失控时，中央银行会作为最大的 NPC 调控市场端货币和战略商品储备；普通波动先由国际市场自行消化，只有库存或现金进入危机区间时才触发央行介入。

商品行情会按 MC 日聚合并保存最近 120 天 OHLCV 数据。GUI 的“K线”视图可切换 30/60/120 天，显示开高低收、成交量、MA5、MA10 和悬停详情；无成交日沿用前收并记零成交量，从未成交的商品不会生成虚假价格。

### 公司系统

玩家可以创建公司，公司每天自动生产商品，并把一部分产出出售给国际市场换取现金。公司拥有现金、库存、经营策略、生产线等级、仓储等级和管理等级。

玩家公司支持：

- 调整经营策略
- 调整自动出售比例
- 升级生产线、仓储、管理
- 注资和提款
- IPO 上市融资

未上市公司不会向普通玩家公开真实估值；玩家公司栏只展示玩家自己的公司。

### 股票系统

系统初始公司默认上市，并自动生成股票。玩家公司可以通过 IPO 上市。股票系统支持：

- 股票持仓
- 限价订单
- 订单簿撮合
- 做市商兜底流动性
- 成交记录
- 公司分红
- 公司盈利统计
- 周期性分红
- 条件委托：止盈、止损

股票价格由公司基本面、行业景气、交易动量和市场噪声共同决定。商品价格持续下跌时，会通过库存折价、利润恶化和行业风险折扣影响股票基本面，避免商品市场与股市走势脱钩。

股票行情与商品共用日 K 线基础设施，并在 GUI 中显示涨跌幅、最高价、最低价、成交量、蜡烛图、成交量柱和均线。

上市公司会累积可分配利润；到达管理员设置的分红周期后，系统会按股东持股比例自动分红，并将分红写入交易记录。股票详情页会显示预计分红和最近历史分红。

玩家可以为已有股票持仓设置止盈或止损条件委托。市场价格达到触发价后，系统会自动按当前价提交卖出委托；如果触发时股票不存在或持仓不足，条件委托会自动取消并写入交易记录。

上市公司可以发起增发融资项目，设置增发数量、发行价格和融资目标。玩家可在融资期限内认购新增股票；达到目标后，公司获得融资资金、投资者获得新增股份，总股本同步增加；未达目标到期则自动退款。

公司会按经营周期自动生成简要财报，记录收入、支出、净利润、资产、负债、现金余额，以及利润和资产相对上一期的变化。股票估值会参考公司的最新财报资产与利润数据。

上市公司支持股东提案与投票。公司管理员可创建分红、增发、改名和资金用途提案；股东按持股数量获得投票权，提案会记录创建时投票权快照并要求最低参与率，投票结束后系统会按设定通过比例自动执行通过的提案，并保留历史结果。分红提案只影响本公司，不会修改其他公司的分红策略。

公司现金长期低于运营安全线时会进入破产风险状态；风险持续到期后会触发破产退市，停止股票新交易，撤销相关挂单，按持股比例清算剩余资产，并从公司和股票列表中移除。

### 指数、信用与债务市场

金融周期使用世界持久化的 MC 日推进，服务器重启、时间跳跃或时钟回退不会重复执行付息、到期和日结。系统按日维护综合股票指数、综合商品指数和各公司行业指数；股票上市、退市或增发时会调整指数除数，避免成分变化被误算成行情涨跌。

公司信用等级从 `AAA` 到 `D`，参考资产、现金、利润、杠杆、风险状态和历史违约。信用等级决定债务上限和风险利差。管理员维护的基准利率只影响新发行债券和新发放贷款，不会追溯修改已有合约。

玩家公司可在“金融 → 公司债”中发行债券。认购资金先进入托管账户，认购期结束后才转入公司；认购中的最大发行本金会立即占用债务额度。系统按周期自动付息，并在到期日结算尾期票息后偿还本金。公司现金不足时合约进入违约，破产清算时债权人先于股东获得清偿；未清偿债权会继续保留，不会因退市而被静默删除。

生效中的公司债可在“金融 → 债市”挂限价买卖单。买单从提交到撤销或成交期间持续冻结限价资金，卖单持续冻结对应债券；撮合遵循价格优先、同价时间优先，支持部分成交、价格改善退款、禁止自成交，并在到期、违约或破产时自动撤单。成交价来自玩家订单簿；参考价则把剩余票息和本金按“当前基准利率 + 公司信用利差 + 期限利差”简化折现。GUI 同时显示市场隐含收益率与参考收益率，两者不会改变发行时锁定的合同票息。应计利息按上次付息日至当前日线性累计。

“金融 → 票据”提供 7、30、90 MC 日央行票据。认购时按当日基准利率加期限溢价锁定收益率，资金进入央行储备账户；到期由统一金融日程一次性兑付本金和利息。央行储备不足时只创造本次兑付缺口，并写入专用交易流水、央行摘要和风险仪表盘，不会静默设置无限余额。第一版央行票据不开放二级交易。

### 商品期货与保证金

管理员可为已注册商品创建标准现金交割期货。报价单位是“每个商品单位的最小货币单位”，每份合约默认代表 10 个商品单位，因此 `名义价值 = 报价 × 合约乘数 × 手数`。玩家先把普通账户资金转入独立保证金账户，再通过限价订单建立多头或空头净持仓；成交不会转移整笔名义本金。

期货订单遵循价格优先、同价时间优先，支持部分成交、撤单和禁止自成交。反向成交会先平掉已有净持仓，超出部分才反手开仓。活跃订单冻结最坏成交情况下的增量初始保证金；持仓和订单占用的资金不能转回普通账户。默认初始、维持和强平保证金率分别为 20%、12% 和 8%。

每个已完成 MC 交易日执行一次盯市。达到最低成交量时使用期货收盘价，否则沿用前结算价或有效现货价，并把结算价限制在现货参考价附近。多空盈亏精确对称；亏损方资金不足时依次使用其可用保证金、清算保障基金，仍不足则按盈利方应收比例削减，不会为普通衍生品亏损铸币。

低于维持保证金会进入追加保证金状态并禁止扩大风险；低于强平线后先撤单，再按风险贡献逐份平仓，达到安全线即停止。无真实流动性时由有上限不利滑点的系统清算成员接管仓位，所需抵押来自保障基金。最后交易日只允许降低风险并在收盘后撤销全部订单；到期使用最近有效现货收盘价窗口现金交割，释放持仓保证金且只执行一次。

玩家公司也可申请央行贷款。贷款在发放时锁定利率，按 MC 日计息，支持提前还款；未按期偿付会依次进入逾期和违约。公司财报中的负债会纳入未偿债券与贷款，并进一步影响股票基本面和信用等级。

### 价格提醒

玩家可以为商品或股票设置目标价格提醒，支持“涨到指定价格”和“跌到指定价格”两种方向。行情刷新后，系统会检查玩家提醒；触发后发送游戏内消息，并自动关闭该提醒，避免重复刷屏。

### 事件系统

市场事件会随机触发，对商品行情产生临时影响：

| 等级 | 影响幅度 | 持续时间 |
| --- | --- | --- |
| 小事件 | 约 ±5%~10% | 0.5~1 MC 天 |
| 重大事件 | 约 ±15%~25% | 1~3 MC 天 |
| 黑天鹅 | 约 ±40%~60% | 2~5 MC 天 |

## GUI 操作

可以通过以下方式打开金融中心 GUI：

- `/market gui`
- `/finance gui`
- 默认快捷键 `F`

普通玩家可见 10 个标签页，管理员可见额外的仪表盘和管理标签页。

| 标签页 | 功能 |
| --- | --- |
| 行情 | 查看国际市场行情，选择商品并进行国际市场买卖；点击“K线”查看 30/60/120 天 OHLCV |
| 交易 | 创建 P2P 商品买单/卖单 |
| 订单 | 查看、吃单或取消商品市场挂单 |
| 库存 | 查看余额、虚拟商品库存和背包数量，进行存入/取出 |
| 公司 | 创建公司、管理自己的公司、查看最新财报与破产风险、发起 IPO；上市后可发起增发融资和股东提案投票 |
| 股票 | 查看上市股票、K 线和均线，下单交易、查看持仓，设置和取消止盈/止损条件委托，并认购增发股票 |
| 记录 | 查看自己的交易记录；管理员可查看全部记录 |
| 资产 | 查看现金、商品、股票、公司债和央行票据价值，以及总资产、今日盈亏和资产占比 |
| 提醒 | 为商品或股票设置涨到/跌到目标价提醒，并查看或取消自己的提醒 |
| 金融 | 在“指数/发行/债市/持仓/票据/贷款/期货”中管理固定收益、贷款与商品期货；期货页支持保证金转入/转出、买卖、撤单和管理员标准合约创建 |
| 仪表 | 管理员查看货币总量、成交量、价格指数、破产风险和央行最近干预 |
| 管理 | 管理员添加/删除商品 |

金融页输入说明：发行页依次填写面值、数量和票息基点；债市页填写每张限价和数量；票据页填写本金并选择 7/30/90 日期限；贷款页依次填写金额、期限和还款间隔；期货页依次填写保证金金额/限价、手数和新合约期限。所有参数均由服务端重新校验。

管理员商品管理页支持：

- 从手中添加：识别手持物品并添加为商品。
- 常用物品：按分类快速添加常见 Minecraft 物品。
- 已注册商品：查看和删除已注册商品。
- 价格历史：清理商品、股票或全部价格历史快照；只影响趋势图历史，不修改当前价格。
- 分红设置：调整全局分红比例和分红周期。

### 服务器配置

首次启动后 Forge 会生成 `config/finance-common.toml`。第三阶段新增的主要默认项如下：

```toml
[financialProducts]
defaultBenchmarkRateBasisPoints = 500 # 5.00%
maxCorporateBonds = 256
maxCompanyLoans = 256
loanGraceDays = 3
indexBasePoints = 1000
annualMcDays = 365
maxBondTermDays = 3650
maxBondFinancingRatio = 0.8
maxLoanTermDays = 3650
maxContractRateBasisPoints = 10000
mediumDefaultRatePercent = 5.0
highDefaultRatePercent = 20.0
creditAaaMinimumScore = 90
creditAaMinimumScore = 80
creditAMinimumScore = 70
creditBbbMinimumScore = 60
creditBbMinimumScore = 45
creditBMinimumScore = 30
```

所有金融参数都有服务端上下界；客户端输入不能突破配置限制。为避免运行中的已发行合约被改写，修改公共配置后应完整重启服务器；基准利率的游戏内调整只作用于之后创建的债券和贷款，不追溯已有合约。

## 服务器配置

模组会注册 Forge COMMON 配置，服主可以在配置文件中调整经济平衡参数，不必重新编译模组。当前集中配置的参数包括：

- 默认公司分红比例与默认分红周期。
- 破产风险持续天数和现金安全线倍率。
- 股东提案最低参与率。
- 每名玩家的价格提醒上限和股票条件委托上限。
- 股票做市商价差。
- 公司 IPO 费用。

游戏内经济周期使用世界持久化时间 `overworld().getGameTime()` 计算 MC 天数，因此服务器重启不会重置融资期限、投票截止、分红周期或破产倒计时。

详细中文说明和默认配置示例见 [docs/CONFIG_ZH.md](docs/CONFIG_ZH.md)。

## 数据存储

数据保存在世界存档 NBT 中，服务器重启后会恢复。

| 数据名 | 内容 |
| --- | --- |
| `finance_data` | 账户、交易记录、订单、行情、事件、公司、公司财报、破产风险、股东提案、股票、股票订单、成交历史、持仓、商品定义、今日资产基准、价格提醒、股票条件委托、公司融资项目、商品与股票最近 120 天日 K 线；交易记录包含时间、玩家、类型、金额、数量和对象名称 |
| `finance_inventory` | 玩家和系统账户的虚拟商品库存 |

加载世界数据时，模组会先清空内存中的静态经济状态，再从当前世界存档恢复，避免连续切换世界时出现跨世界数据残留。

- 管理员“仪表”页展示货币总量、玩家可用/冻结资金、公司现金、NPC 市场资金、央行储备、当日商品与股票成交量、价格指数、风险公司数量和最近 30 个 MC 日趋势。

- `finance_data` 当前数据版本为 `DataVersion = 24`。旧存档没有保险数据时不创建玩家保单或理赔；系统保险池在首次保险周期或操作时初始化，既有账户、持仓、贷款与基金数据保持不变。
- 商品和股票成交量只在结算成功后计入指标；撤单、被拒绝的下单和读取历史记录不会增加成交量。

### 企业风险保险

金融页新增“保险”子页。玩家公司可购买库存灾害险和营业中断险，商业银行可为真实公司贷款购买信用险。保单次日生效，保障限额、免赔额、赔付比例、期限和保费均由服务端报价；同一对象的重叠保障、重复请求和客户端伪造损失会被拒绝。

理赔只接受服务器生成并可核验的库存扣减、经营停摆和贷款违约事件。赔款不足时保留未付债权，后续批次继续支付；信用险赔款同步冲减银行账本贷款资产与贷款合同本金。管理员可查看保险池资金、总风险敞口和待赔金额，普通玩家只看到自己的保单、理赔和公司风险摘要。

### 管理员稳定性诊断

- `/finance status`：查看数据版本、各模块 `ACTIVE/READ_ONLY/PAUSED` 状态和最近一次检查摘要。
- `/finance diagnose`：运行只读全局一致性检查，检查账户、订单、债券、贷款、银行、期货、系统资金池、K 线和金融日程。
- `/finance resume <module>`：模块修复后重新检查；只有无 `ERROR/FATAL` 时才恢复写入。诊断命令不会自动清空、注资或改写资产。

世界载入后会把检查拆成多个 tick 执行。检测到致命局部损坏时，对应模块暂停写入，其他模块继续运行；诊断报告和暂停原因会随世界存档保存。
