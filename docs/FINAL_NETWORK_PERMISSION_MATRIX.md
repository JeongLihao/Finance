# 最终网络与权限矩阵

网络协议版本：8。所有 C2S handler 都以 `context.getSender()` 作为身份，不接受客户端玩家 UUID。响应集合均有固定上限；市场数据请求还有按玩家速率限制和短窗口去重。

| 入口组 | 解码边界 | 服务端上下文与权限 | 重放/失败边界 |
| --- | --- | --- | --- |
| 商品交易、库存、股票交易/订单 | 商品 64、物品 128、symbol 16；数量价格必须正数且防乘法溢出 | manager 重算报价、余额、库存、上市状态 | 结算失败不推进订单；撤单精确解冻 |
| 仓库操作 | 商品与操作键各 64，单次请求 ≤1,000,000 | 必须是当前 `WarehouseMenu`、同 warehouse UUID、`stillValid` 校验维度/距离/方块；服务层复核所有权/公司角色 | 操作键幂等；背包计划变化整笔回滚 |
| 合同接受/交付 | UUID + 64 操作键 | 当前仓库、期限、接受者、真实物品和 escrow 由服务端重算 | 不足量、满仓、支付失败均不移动资产 |
| 公司世界操作 | 文本/操作键 64，合同数量与奖励各 ≤1,000,000 | 当前公司菜单、公司 UUID、距离、办公桌身份和成员角色 | 邀请、角色、生产、升级和发布各自幂等 |
| 密封货箱/物流 | 运单/仓库/令牌 UUID，商品 64，数量有配置硬上限 | 源/目标实体设施、持有人、公司物流权限、运输托管令牌 | 复制或篡改显示 NBT 不改变权威货物；重复卸载失败 |
| 聚落需求 | 枚举、聚落/需求 UUID、操作键 64 | 接取/交付均要求对应贸易站、同维度和近距离 | 需求状态与操作键阻止重复付款 |
| 探索调查 | 没有 C2S 坐标包 | 目标由服务端从有界已登记设施选择；完成只能由目标方块服务端 `use` 路径触发 | 凭证 NBT 只有任务 UUID；伪造位置与重复交互无效 |
| 公司治理 | UUID、枚举、文本/操作键和期限上限 | 菜单、持股快照、公司角色和已通过授权均重新验证 | 跨公司任务失败保留重试；原子资金/库存交割 |
| 银行、基金、期货、保险 | 枚举与数值范围、响应行数上限 | 服务层重算报价、准备金、保证金、保单资格和所有权 | reference/状态机防重放，失败保留原账务 |
| 管理员操作与央行 | 字符串上限、合法 ResourceLocation、二次确认 | `hasPermissions(2)`，央行实体入口和服务端重算 | 普通客户端无法通过伪造 GUI 获得权限 |

红队自动化覆盖超长/空字符串、未知枚举、负数、零、溢出、错误 UUID、乱序旧响应、重放操作键、自成交、满账户、满仓、损坏货箱 NBT 和重复交割。未发现自动化可复现的资产复制或私有数据越权。

仍需真人专服执行：破坏菜单方块后的延迟包、退出公司同时双击、两客户端竞争同一任务、管理员降权后的已打开菜单以及高延迟乱序。任一资产复制、远程设施操作或私有数据泄露均为发布阻断。
