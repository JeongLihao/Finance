## 最终结论

**尚未达到正式发布标准。**

代码、资源、无头游戏测试、专服启动和发布包审计均已通过；但是本计划要求的真人双客户端完整端到端流程、全部入口在 GUI Scale 2～4 下的目视检查、真实旧世界副本连续重载，以及启用随机世界生成前的五 seed 验收没有在本轮全部完成。自动化测试和过去的局部联机证据不能替代这些发布门槛。

## 本轮冻结与实现范围

- 没有新增金融产品、机器、NPC AI、结构类型或美术资源。
- 复核并记录四条玩家路线：生存交易、实体物流协作、公司经营、可选高级金融。
- 新增三套配置预设：`minecraft_first.toml`、`casual_server.toml`、`legacy_finance.toml`。
- 新增中英文翻译严格对齐、配置预设约束、RC 协作规模保存/加载测试。
- 最终代码核验为主金融菜单所有字符串和集合增加明确协议边界，锁定旧网络包传输方向，并清理聚落/探索失败生成或历史裁剪留下的零余额托管账户。
- 补齐网络权限矩阵、无障碍检查表、资产去向图、存档兼容策略和发布包审计脚本。

股票、基金和保险目前没有统一的“禁止新业务”总开关，不能声称它们可按产品完全禁用；它们仍通过证券终端作为可选后期内容。期货与银行已有独立配置边界。该限制已作为后续配置设计事项保留，不在冻结阶段引入新的大规模配置框架。

## 资产、权限和兼容性结论

- 货币、商品、合同 escrow、公司 custody、物流 escrow 和聚落/调查奖励均有明确来源、托管与失败恢复路径；配置预设不改变资产守恒规则。
- 客户端只提交意图；身份、角色、距离、方块实体、数量/价格上限、状态、操作键与权限由服务端重新校验。详见 [FINAL_NETWORK_PERMISSION_MATRIX.md](FINAL_NETWORK_PERMISSION_MATRIX.md)。
- `DataVersion=33` 与网络协议 `8` 未因本轮文档和预设工作变化。迁移节点、坏记录隔离和恢复边界见 [SAVE_COMPATIBILITY_POLICY.md](SAVE_COMPATIBILITY_POLICY.md)。
- 实验性随机世界生成在所有预设中保持关闭。蓝图和战利品资源存在不等同于已启用或已通过五 seed 验收。

## 正式发布前必须完成

1. 使用独立专服、普通玩家 A/B 和管理员实际完成仓库存取、市场交易、合同 escrow、货箱运输、公司邀请/生产、聚落交付和调查结算，并在服务器重启后复查。
2. 在 GUI Scale 2、3、4 下逐入口检查 960×540 及常见分辨率，覆盖长中英文、tooltip、滚动、键盘焦点、状态灯、声音、粒子和 Advancement toast。
3. 在真实旧版本世界副本上连续执行至少三次加载/保存/重启，核对账户、冻结资金、订单、公司、债务、仓库、运单、聚落和调查任务的业务含义。
4. 若准备启用随机遗迹世界生成，先完成至少五个 seed 的频率、边界、战利品和旧区块兼容验收；否则继续保持默认关闭。
5. 用实际发行启动器验证客户端和专服的正常关闭路径，并记录崩溃报告与最终日志为空。

完成上述阻断项并保存证据后，才可将本报告状态改为“达到发布标准”。

## 已知非阻断代码债务

- `FinanceScreen.java` 仍约 3,286 行。菜单数据和若干轻量入口已经拆分，但高级金融主屏仍是高回归风险单体；继续开发前应按标签/领域逐步拆分，避免在 RC 冻结期一次性重写。
- Forge 47.4.16 编译会对 `FMLJavaModLoadingContext.get()` 和 `ModLoadingContext.get()` 报移除预警；当前运行正常，需在升级 Forge 目标时按对应 API 生命周期处理。
- Forge GameTest 任务仍会报告 ForgeGradle 所使用的 Gradle 9 不兼容弃用项；普通 `help --warning-mode all` 未发现本项目脚本自身的新警告。
- 版本检查提示 Forge 47.4.23 可用；当前仍以计划锁定的 47.4.16 构建，升级应单独执行客户端、专服、网络和存档兼容回归。
