# Finance — Minecraft 服务器金融系统模组

Finance 为 Minecraft Forge 服务器加入一套虚拟经济、商品交易、公司经营、股票市场和中央银行调控系统，并扩展公司财报、融资增发、股东投票、分红、公司债券、贷款、信用评级、指数和破产退市等完整公司生命周期玩法。金融层下面还有一层会自己运转的宏观实体经济：聚落人口、本地物价、雇工，由中央银行用利率、准备金率、公开市场操作和商品平准调控总体物价。

- 版本：v0.4.1（v0.4.2 宏观实体经济开发中）
- 平台：Minecraft 1.20.1 / Forge 47.4.16
- 作者：H-Jeong
- 更新日志：[CHANGELOG.md](CHANGELOG.md)

> README 只保留模组介绍、安装方式和游戏内操作说明；版本变化和修复记录请查看更新日志。

核心玩法不是从全屏表格开始，而是“采集真实物品 → 仓库存取 → 市场出售/履约 → 公司设施生产 → 上市后进入高级金融”。股票、债券、基金、期货和保险是这条 Minecraft 主循环之后的深度层。商品价格随供需和 NPC 市场变化，股票价格参考公司基本面，中央银行在市场失控时介入；单人游玩时，NPC 做市商和 NPC 投资者提供对手盘与股东。

## 安装

1. 安装 Minecraft Forge 1.20.1，推荐 Forge 47.4.16。
2. 将 Finance 模组 JAR 放入服务器或客户端的 `mods` 文件夹。
3. 启动游戏或服务器。

客户端可选安装 **Ponder 1.0.92+（1.20.1）** 观看动画教学；不安装不影响任何玩法。

## 推荐游玩路线与场所

进度页按“金融账本 → 市场终端 → 仓库 → 存入商品 → 世界交易 → 合同 → 公司协作 → 公司生产 → 可选证券终端”逐步引导，并分阶段解锁配方。右上角目标卡由服务端真实进度驱动；目标完成时会播放一次本地提示与音效并自动切换下一步，登录同步不会重复提示。按 `J` 打开教程中心，可查看九阶段状态、悬停阅读当前操作提示、进入完整手册或切换目标卡；按 `U` 也可直接隐藏目标卡。这些引导均不依赖其他模组。

九阶段主线完成后，目标卡与教程中心会继续引导实体物流、村庄援助、野外调查、高级金融、产业融资和风险管理六条可选路线。可选路线可以按任意顺序完成，也可以在教程中心点击卡片主动追踪；已有里程碑会被识别，不要求玩家重做。

安装 Ponder 后，对便携账本、仓储控制器、市场终端、公司工厂、密封货箱、聚落贸易站、调查板和证券终端按住 Ponder 的观察键，即可播放十三组动画教学；不安装时配方、进度、目标卡与手册仍完整可用。Ponder 只负责展示临时场景，不读写真实账户、仓库或市场数据。

仓库之间的商品不会通过菜单瞬移。使用密封运输货箱时，先在目的仓库绑定，再在源仓库用副手商品堆叠选择装货量，最后通过玩家背包或原版运输载体把货箱实际送达。货箱标签不保存可信商品，损毁后可回源仓库签发替代凭证。

村庄附近可以建设聚落贸易站。公共食物、材料、防御和重建需求都由现有 NPC 预算预存 escrow，玩家必须在贸易站附近接取并带真实物品回来交付；系统不会给每个村民创建账户，也不会让村庄需求直接操纵全服市场价格。

资源调查板会从同维度、有限半径内已经登记的聚落或仓库中选择一个真实目的地。调查凭证只包含任务编号，方向和距离由服务器按需计算；必须在对应设施实际交互才能领取预存奖励。首版遗迹自动生成默认关闭，不修改原版矿物、地形、村庄或旧区块。

| 场所 | 普通用途 | 权限与数据边界 |
| --- | --- | --- |
| 金融账本 | 余额、冻结资金、本人近期记录 | 只同步本人轻量数据 |
| 市场终端 | 商品价格、涨跌、今日短缺与合同机会 | 最多 64 行，不发送订单 UUID/完整历史 |
| 仓储控制器 | 真实物品存取、合同接受与交付；显示总量/质押/可用量 | 持续校验所有权、维度、距离和方块身份 |
| 聚落贸易站 | 村庄公共需求、实物交付、贡献关系；领取《金融周报》 | 仅同步公共任务与本人贡献；拆除保留 escrow |
| 资源调查板 | 获取有方向提示的聚落/仓库调查任务 | 不扫描未加载区块；一个玩家最多一个活动目标 |
| 公司办公桌/工厂 | 成员、仓库、设施、采购、生产与资本项目 | 角色权限由服务端校验 |
| 银行柜台 | 存取、定存、公司贷款、真实库存质押和公开风险灯 | 质押要求有效柜台会话；普通响应不含完整总账或监管后台值 |
| 董事会桌 | 上市公司股权、提案、投票与授权执行 | 桌面绑定不授予投票权，仍按登记日持股判断 |
| 证券终端 | 股票、债券、基金、期货、保险、区域行情与经营对冲 | 需要靠近终端；对冲目标不会自动交易 |
| 中央银行控制台 | 指标、政策、诊断和管理操作 | 仅 2 级管理员；高风险操作需再次确认 |

市场短缺、银行限制、公司风险和重大事件会通过对应场所附近或参与者通知反馈。全服重大事件广播可在服务器配置中关闭。价格提醒即使在玩家离线时触发，也只会保存有限通知并在下次登录发送一次。

所有金融设施使用模组自己的 16×16 原版像素密度贴图，配色为石墨钢、黄铜、青绿和胡桃木，不以原版金属块或混凝土代替。设备顶面嵌入式状态灯统一为绿色正常、黄色警告、橙色受限/满载、红色风险/处置、灰色离线（聚落贸易站用遮阳棚颜色表示，红色为关门）；状态变化不会遮掉市场、证券、银行等设施本身的外观身份。

## 功能概览

### 账户与商业银行

每个玩家都有独立银行账户，支持余额查询、转账、交易扣款、订单资金冻结和取消返还。新玩家首次加入会自动获得初始资金。

这里的“普通账户”是玩家钱包，不是商业银行存款。金融界面的“银行”分页提供系统商业银行：把钱包资金存入后，钱包减少、银行准备金资产与客户存款债权同时增加，不会把同一笔钱重复计算。玩家可以办理活期存取、锁定利率的定期存款和跨行支付；公司所有者还可申请商业银行贷款，并把公司银行存款提取到公司现金。

商业银行采用复式总账，持续核对“资产 = 负债 + 权益”。跨行支付会同步移动付款行和收款行的准备金；同行支付只调整客户明细，不虚构准备金流动。公司贷款会同时形成银行贷款资产和公司存款负债，利率由基准利率、公司信用、期限与银行利差组成。坏账计提贷款损失准备，资本或流动性不足会限制新增业务；流动性缺口先尝试同业隔夜拆借，再使用有总额和惩罚利率限制的央行最后贷款人安排。

存款保险按“同一客户、同一家银行、活期与定期合并”计算，默认保障上限为 100,000。进入处置的银行只把受保部分迁移到桥接银行，未受保部分仍留作原银行债权；同一银行不会重复赔付。普通玩家只会收到公开利率与风险指标，完整资产负债表和处置操作仅对管理员开放。

### 中央银行、利率与央行债券

中央银行是模组里最高的经济主体：只管货币和物价，不收税、不发福利，也没有“国家”和“政府”。

- **物价目标**：央行盯住年化 2% 的通胀（`centralBank.inflationTargetBps`），通胀在目标 ±1% 以内视为物价稳定。
- **央行基准利率**：按类 Taylor 规则自动计算目标利率（中性利率 + 系数 ×（通胀 − 物价目标）− 衰退指标），每 30 个 MC 日议息一次，议息前 3 天给出方向性前瞻指引并全服公告。支持 `AUTO` / `ADVISORY` / `MANUAL` 三种模式。活期、准备金和同业利率每日浮动；定存、贷款、债券和票据在发放时锁定利率，调息不会追溯。有聚落数据时，通胀使用消费篮子 CPI。
- **银行定期存款**：期限 7 / 30 / 90 MC 日，利率为基准利率加点差并在存入时锁定，到期一次性付息。提前支取只退本金，已计利息全部罚没。
- **存款准备金率**：议息日通胀高出目标两倍容忍区间时上调 0.5%，低于目标两倍区间或经济明显疲软时下调 0.5%（活期 5%～20%，定期为活期的一半）。商业银行的法定准备金随之变化。
- **公开市场操作**：央行每天向商业银行卖出央行票据（吸收超额准备金）或买回票据、做回购（投放），把各行超额准备金调向目标；通胀越高目标越低，银行可放贷的余钱越少。只吸收超额部分，不会把银行压到法定准备金以下。
- **商品平准**：食物、住房、取暖、衣物等消费品的国际市场价格偏离基准价 15% 以上时，央行用战略储备卖出（平抑高价）或收储（托住低价），每种商品每天最多动参考库存的 5%。
- **央行债券**：央行发行 30 / 90 / 180 天无风险债券，收益率为基准利率加期限溢价，认购时锁定、到期自动兑付；提前赎回只返还本金。
- **银行挤兑**：每家银行每天更新恐慌度（0–100），受有效准备金率、资本充足率、提现占比、同业倒闭传染和真实风险触发的谣言影响。恐慌升高会引发提现潮，依次动用自有准备金、同业拆借和央行惩罚利率贷款；恐慌 ≥ 60 时全行限提，持续无法兑付的银行进入破产处置，未保险部分按比例赔付。
- **玩家开银行**：缴纳牌照费并实缴资本金后可开设自己的银行，自定存贷利差揽储放贷，接受与 NPC 银行相同的准备金、资本充足率和存款保险监管。所有者名下公司默认不能向自家银行贷款；银行破产时所有者剩余股权会被核销。

> 央行概况、央行债券认购/赎回和定存提前支取在金融中心标题栏“更多操作 → 中央银行”；开定存和到期兑付在银行页。做市、村庄、挤兑、公开市场操作、商品平准和财报季由服务端每日自动运行。

### 商品与仓库

模组默认注册以下基础商品，管理员可以在 GUI 中添加更多 Minecraft 物品作为可交易商品：

| 商品 | 对应物品 | 分类 |
| --- | --- | --- |
| 铁锭 | `minecraft:iron_ingot` | 原材料 |
| 小麦 | `minecraft:wheat` | 食物 |
| 石头 | `minecraft:stone` | 建筑方块 |
| 面包 / 木头 / 煤 / 羊毛 | 宏观经济新增，供聚落人口消费与替代 | 食物、住房、取暖、衣物 |

商品托管账本仍是市场的权威库存；玩家需要制作并放置“仓储控制器”，在附近打开实体仓库，把背包中的基础物品原子存入托管，或把未被挂单锁定的托管商品完整提取回背包。命名、附魔、带特殊 NBT 或有耐久的物品不会被当作普通商品吞入。

每个个人仓库默认提供 4096 商品单位容量，同一玩家的有效仓库容量会相加。旧世界已有托管资产不会迁移或删除；当已用量超过现有容量时，只禁止继续存入，提取、出售和订单结算仍可进行。拆除控制器也不会掉落或清空托管资产。

仓库界面还会显示 NPC 市场因库存短缺发布的采购合同。奖励在发布时从国际市场账户转入独立托管账户；玩家在自己的仓库接受合同，并在截止日前从真实背包一次性交付全部物品。成功后奖励从托管账户转给玩家；未完成合同到期时，剩余奖励原路退还，不会凭空发币或重复领奖。

### 商品市场

Finance 包含两套商品市场：

- P2P 市场：玩家之间挂限价买单/卖单，价格匹配时自动撮合，支持部分成交和取消订单。
- 国际市场：系统做市商提供即时买卖报价，市场库存、成交动量、供需趋势和噪声共同影响价格。

市场失控时，中央银行会作为最大的 NPC 调控市场端货币和战略商品储备；普通波动先由国际市场自行消化，只有库存或现金进入危机区间时才触发央行介入。

市场事件会随机触发，对商品行情产生临时影响：

| 等级 | 影响幅度 | 持续时间 |
| --- | --- | --- |
| 小事件 | 约 ±5%~10% | 0.5~1 MC 天 |
| 重大事件 | 约 ±15%~25% | 1~3 MC 天 |
| 黑天鹅 | 约 ±40%~60% | 2~5 MC 天 |

### 专业行情详情

商品和股票共用服务端日 K 行情，按 MC 日聚合并保存最近 120 天 OHLCV；无成交日沿用前收并记零成交量，从未成交的商品不会生成虚假价格。进入商品或股票页、选择标的后点击“K线”，可选择最近 30、60 或 120 个 MC 日；详情页保持在 400×250 主窗口内，通过 `K+MA → MACD → RSI → Book → Trades → Ranks → VolRank` 循环按钮切换：

- `K+MA`：OHLCV 蜡烛、成交量、MA5 与 MA10；当天尚未收盘时会显示“进行中”。
- `MACD`：EMA12、EMA26、DIF、DEA9 与柱状差值。
- `RSI`：标准 Wilder RSI14，并标出 70/30 参考线。
- `Book`：商品或股票真实限价单聚合出的买卖五档，不发送完整订单簿和玩家 UUID。
- `Trades`：当前标的最近 20 笔成交，按新到旧显示 MC 日、时间、方向、价格和数量。
- `Ranks` / `VolRank`：商品与股票分别计算涨幅、跌幅、成交量和放量 Top 5。

行情按标的按需加载；快速切换标的或 30/60/120 日窗口时，迟到的旧响应不会覆盖当前图表。加载中、空历史和服务器响应较慢会显示不同状态。

### 价格提醒

玩家可以为商品或股票设置“涨到指定价格”或“跌到指定价格”提醒，还支持“突破前一完整交易日最高价”和“跌破前一完整交易日最低价”。提醒基于服务端行情判定，触发后发送游戏内消息并自动关闭，避免重复刷屏。

### 公司系统

公司同时支持旧式自动经营与世界化经营。旧存档公司保持 `LEGACY_AUTOMATIC`，新公司默认使用 `HYBRID`（服主可改为纯 `PLAYER_DRIVEN`）：玩家放置公司办公桌、绑定公司仓库和工厂控制器后，设施每天至多处理一次，产出进入由公司 UUID 稳定派生的独立托管库存。设施成功生产时不会再执行同日旧式生产；无法生产时，HYBRID 才按配置使用低效率兜底。

公司办公桌提供 320×240 的轻量界面，用于查看本公司的成员、仓库、设施、采购合同和风险状态。所有者可邀请成员并分配经理、财务、仓库员工或普通成员角色；客户端按钮只作提示，邀请、角色、仓库存取、升级、采购和高级治理权限均由服务端再次验证。工厂控制器会以绿/黄/橙/红/灰状态显示正常、缺料、满仓、风险和停用（宏观经济开启后还有“缺人手”），并在成功日结时提供一次轻量反馈。

公司仓库中的商品只归公司 custody 所有，不记到任意成员名下。`PLAYER_DRIVEN` 只使用 custody；`HYBRID` 消耗时先使用 custody、再使用不重复计数的旧 `Company.inventory`；旧式公司继续使用原库存。设施升级由服务端计算现金和材料成本，采购合同从公司现金转入独立 escrow，失败、取消或破产时按原路径补偿，不凭空复制资金或物品。

玩家公司支持：

- 公司办公桌、成员邀请与角色权限
- 公司仓库绑定、工厂控制器、每日生产和设施升级
- 用原版工作方块搭厂房，按设备选择手工/改良/工业生产方式

**NPC 竞争公司**：系统公司和后来出现的 NPC 公司各有经营人格（激进、保守、投机），会换策略、升级产线、在原料紧张时发采购合同和你抢供应，满足条件后上市（规则与玩家 IPO 相同）。某种产品明显紧缺时会有新竞争者入场，无主公司总数默认最多 6 家，见服务器配置 `rivals` 分组。开启 `hostileTakeovers` 和 `activismEnabled`（或直接用 `config-presets/solo_play.toml` 单人经营配置档）后，NPC 公司还会对股价明显低估的上市公司建仓并发起敌对要约，或者以大股东身份要求你提高分红；回购、提高分红和增持是你的防御手段。在公司治理页能看到各类 NPC 股东的持股、情绪和对提案的表态，在金融终端“宏观”页签按“对手”查看竞争公司。
- 使用公司现金发布采购合同，合同交付进入公司托管
- 托管产出自动出售并计入公司现金与财报流水
- 调整经营策略和自动出售比例
- 升级生产线、仓储、管理
- 设定日工资，从附近聚落雇工（宏观经济）
- 注资和提款
- IPO 上市融资

未上市公司不会向普通玩家公开真实估值；玩家公司栏只展示玩家自己的公司。

**实体资本项目**：公司绑定仓库和工厂后，可在对应控制器附近创建升级项目。预算和材料需求在创建时由服务端冻结；上市公司走一次性股东提案授权，超过治理阈值的未上市公司由所有者显式确认。融资可以来自留存收益、真实商业贷款、实际完成募集的企业债或真实增发，资金到位后仍必须在设施旁提交公司 custody/玩家背包中的真实材料。项目资金使用独立 escrow；取消只退还尚未使用的项目资金，不会擅自撤销已经成立的贷款或债券；施工任一步失败都会保留可重试项目，并恢复已经移动的资金和材料。完成后的设施容量和生产能力会进入下一期公司财报，再由既有估值模型平滑影响股票、债券信用和基金持仓价值。

**厂房与生产方式**（详见 [docs/COMPANY_FACILITIES.md](docs/COMPANY_FACILITIES.md)）：工厂控制器周围 9×9×5 的范围是厂区，在里面摆原版工作方块（堆肥桶、烟熏炉、高炉、织布机、切石机等）就是设备。每个行业有手工、改良、工业三档生产方式，分别要求设施 1/2/3 级和对应设备；档位越高产量越大，但要烧煤、耗铁。岗位来自设备（每台设备提供固定岗位，受等级上限 20/40/60 约束），直接接到聚落劳动力市场。

- 从控制器打开公司界面会多一个"厂房"页：三档方式卡片逐项列出设备"已有/需要"、投入和产出，满足条件即可"切换到此方式"。切换次日生效，随后 3 天改造期产量减半；打开界面时会用粒子描出厂区范围。
- 每天日结时扫描一次厂区，同一块设备只算给最近的一座工厂。设备被拆走会自动降到能满足的最高档，补齐后自动恢复；连手工档都不满足时停产（"缺设备"，停业险不理赔）。区块未加载时沿用最近一次扫描，最多 7 天。
- 蹲下右键控制器显示"当前方式 · 岗位 · 缺什么"。
- 老存档的工厂先进入 14 天"临时作坊"：按原规则满产，期间补齐设备即自动转正；到期仍没设备则停产。新放置的控制器没有临时作坊。

### 工厂方块

用铁锭、熔炉和箱子合成“工厂”方块，右键打开类似熔炉的界面，服务端会自动生产。第一版内置三条配方：小麦×3 → 面包、铁矿 → 铁锭、橡木原木 → 木板×4。缺料或输出槽满时自动停机，破坏方块会掉落机内物品。

### 股票系统

系统初始公司默认上市，并自动生成股票。玩家公司可以通过 IPO 上市。股票系统支持持仓、限价订单、订单簿撮合、做市商兜底流动性、成交记录、周期性分红和止盈/止损条件委托。

股票价格由公司基本面、行业景气、交易动量和市场噪声共同决定。商品价格持续下跌时，会通过库存折价、利润恶化和行业风险折扣影响股票基本面，避免商品市场与股市走势脱钩。

上市公司会累积可分配利润；到达管理员设置的分红周期后，系统会按股东持股比例自动分红，并将分红写入交易记录。股票详情页会显示预计分红和最近历史分红。

玩家可以为已有股票持仓设置止盈或止损条件委托。市场价格达到触发价后，系统会自动按当前价提交卖出委托；如果触发时股票不存在或持仓不足，条件委托会自动取消并写入交易记录。

上市公司可以发起增发融资项目，设置增发数量、发行价格和融资目标。玩家可在融资期限内认购新增股票；达到目标后，公司获得融资资金、投资者获得新增股份，总股本同步增加；未达目标到期则自动退款。

公司会按经营周期自动生成简要财报，记录收入、支出、净利润、资产、负债、现金余额，以及利润和资产相对上一期的变化。股票估值会参考公司的最新财报资产与利润数据。

上市公司支持股东提案与投票。公司管理员可创建分红、增发、改名和资金用途提案；股东按持股数量获得投票权，提案会记录创建时投票权快照并要求最低参与率，投票结束后系统会按设定通过比例自动执行通过的提案，并保留历史结果。分红提案只影响本公司，不会修改其他公司的分红策略。

公司现金长期低于运营安全线时会进入破产风险状态；风险持续到期后会触发破产退市，停止股票新交易，撤销相关挂单，按持股比例清算剩余资产，并从公司和股票列表中移除。

### 证券市场深化

- **NPC 做市商**：商品、股票和期货市场都有独立出资的 NPC 做市商提供双边报价，单人游玩也有对手盘。做市商不能凭空印钱或交割，按库存偏斜、均值回归和波动率动态调整价差；价格大幅偏离基本面时自动暂停报价。
- **NPC 投资者与股东**：分红派、成长派、短线派、价值派四类 NPC 投资者用 NPC 资金池注资的账户真实买卖股票，并从 IPO 后无人持有的流通股中按 max(现价, 公允价) 配售。单个原型和全部 NPC 对一家公司的合计持股都有上限（低于 50%），不会自动取得控制权。NPC 股东会按各自偏好对提案投票，并在要约价达到所需溢价时接受收购要约。可在配置 `npcInvestorsEnabled` / `npcVotingEnabled` 中关闭，关闭后已有持仓保留。
- **融资融券**：融资最高 2 倍杠杆，首付 50%；融券受单只股票 5% 券池和单人 20% 上限约束，卖出所得冻结，只能用于买回还券。维持担保比例低于 150% 时预警，低于 130% 时强制平仓，穿仓缺口记为不良债务。
- **公司并购 / 要约收购**：持有目标公司 ≥ 30% 表决权股份后，可以按 0.8–1.5 倍公允价发起 3–14 天要约，要约期间目标股票停牌。持股达到 90% 后可以强制私有化并退市。
- **公司财报季**：上市公司每 30 个 MC 日发布季报，按过去 3 期线性外推形成市场预期，预期差驱动股价跳动（单次冲击上限 ±20%），并永久修正一半公允价值。财报只从真实日度流水汇总，历史只增不改。

### 指数、信用与债务市场

金融周期使用世界持久化的 MC 日推进，服务器重启、时间跳跃或时钟回退不会重复执行付息、到期和日结。系统按日维护综合股票指数、综合商品指数和各公司行业指数；股票上市、退市或增发时会调整指数除数，避免成分变化被误算成行情涨跌。

公司信用等级从 `AAA` 到 `D`，参考资产、现金、利润、杠杆、风险状态和历史违约。信用等级决定债务上限和风险利差。管理员维护的基准利率只影响新发行债券和新发放贷款，不会追溯修改已有合约。

玩家公司可在“金融 → 公司债”中发行债券。认购资金先进入托管账户，认购期结束后才转入公司；认购中的最大发行本金会立即占用债务额度。系统按周期自动付息，并在到期日结算尾期票息后偿还本金。公司现金不足时合约进入违约，破产清算时债权人先于股东获得清偿；未清偿债权会继续保留，不会因退市而被静默删除。

生效中的公司债可在“金融 → 债市”挂限价买卖单。买单从提交到撤销或成交期间持续冻结限价资金，卖单持续冻结对应债券；撮合遵循价格优先、同价时间优先，支持部分成交、价格改善退款、禁止自成交，并在到期、违约或破产时自动撤单。成交价来自玩家订单簿；参考价则把剩余票息和本金按“当前基准利率 + 公司信用利差 + 期限利差”简化折现。GUI 同时显示市场隐含收益率与参考收益率，两者不会改变发行时锁定的合同票息。应计利息按上次付息日至当前日线性累计。

“金融 → 票据”提供 7、30、90 MC 日央行票据。认购时按当日基准利率加期限溢价锁定收益率，资金进入央行储备账户；到期由统一金融日程一次性兑付本金和利息。央行储备不足时只创造本次兑付缺口，并写入专用交易流水、央行摘要和风险仪表盘，不会静默设置无限余额。第一版央行票据不开放二级交易。

玩家公司也可申请央行贷款。贷款在发放时锁定利率，按 MC 日计息，支持提前还款；未按期偿付会依次进入逾期和违约。公司财报中的负债会纳入未偿债券与贷款，并进一步影响股票基本面和信用等级。

### 指数基金与长期理财

金融页“基金”子页提供全市场股票指数基金、原材料主题指数基金和货币/短债基金。基金不是复制指数点位：申购资金进入独立托管账户，股票基金通过现有股票订单接口获取真实持仓，货币基金持有现金与真实央行票据，净值由这些底层资产、利息和费用共同决定。

玩家可以输入金额申购、按万分之一份额精度赎回，或设置按 MC 日执行的定投计划。现金不足时赎回会保留为待处理债权并冻结相应份额，不会直接删除持仓；基金页会显示净值涨跌、费用、份额、冻结份额、近期波动和流动性提示。历史不足时风险指标明确显示“数据不足”。

### 商品期货与保证金

管理员可为已注册商品创建标准现金交割期货。报价单位是“每个商品单位的最小货币单位”，每份合约默认代表 10 个商品单位，因此 `名义价值 = 报价 × 合约乘数 × 手数`。玩家先把普通账户资金转入独立保证金账户，再通过限价订单建立多头或空头净持仓；成交不会转移整笔名义本金。

期货订单遵循价格优先、同价时间优先，支持部分成交、撤单和禁止自成交。反向成交会先平掉已有净持仓，超出部分才反手开仓。活跃订单冻结最坏成交情况下的增量初始保证金；持仓和订单占用的资金不能转回普通账户。默认初始、维持和强平保证金率分别为 20%、12% 和 8%。

每个已完成 MC 交易日执行一次盯市。达到最低成交量时使用期货收盘价，否则沿用前结算价或有效现货价，并把结算价限制在现货参考价附近。多空盈亏精确对称；亏损方资金不足时依次使用其可用保证金、清算保障基金，仍不足则按盈利方应收比例削减，不会为普通衍生品亏损铸币。

低于维持保证金会进入追加保证金状态并禁止扩大风险；低于强平线后先撤单，再按风险贡献逐份平仓，达到安全线即停止。无真实流动性时由有上限不利滑点的系统清算成员接管仓位，所需抵押来自保障基金。最后交易日只允许降低风险并在收盘后撤销全部订单；到期使用最近有效现货收盘价窗口现金交割，释放持仓保证金且只执行一次。

### 企业风险保险

金融页“保险”子页中，玩家公司可购买库存灾害险和营业中断险，商业银行可为真实公司贷款购买信用险。保单次日生效，保障限额、免赔额、赔付比例、期限和保费均由服务端报价；同一对象的重叠保障、重复请求和客户端伪造损失会被拒绝。

理赔只接受服务器生成并可核验的库存扣减、经营停摆和贷款违约事件。赔款不足时保留未付债权，后续批次继续支付；信用险赔款同步冲减银行账本贷款资产与贷款合同本金。管理员可查看保险池资金、总风险敞口和待赔金额，普通玩家只看到自己的保单、理赔和公司风险摘要。

### 村庄与商路

- **村民需求经济**：村庄每天按人口和职业补足预算，逐商品采购并消费。报价高于公允价 1.5 倍会被拒买并降低好感；好感降到 −50 时村庄抵制，连续 3 天零成交的行商会撤离 7 天。
- **商队商路**：在两个聚落间建立路线后每天自动发车，利用本地价格差套利，利润扣除货款、保镖工资和保费。被劫概率随距离和袭击警报上升、随保镖等级下降；保费按风险定价，只赔成本不赔利润。路线越繁忙价差越小，套利空间会自动收敛。到货进入目的地聚落托管，供人口消费。

### 宏观实体经济（维多利亚 3 式）

金融层下面有一层会自己运转的实体经济，设计见 [docs/MACRO_ECONOMY.md](docs/MACRO_ECONOMY.md)。

- **人口需求与替代品**：聚落人口按职业需要食物、住房、工具、取暖、衣物五类商品，同一类可由多种商品满足（小麦/面包、石头/木头、煤/木头），按本地价格自动替代。
- **本地价格**：每个聚落每种商品按当天供需算出价格系数（±75%，每天最多变动 10%）。短缺的地方贵，过剩的地方便宜，商队套利也跟着真实供需走。
- **生活水平与人口**：需求满足率决定生活水平，饿肚子时整体打五折；生活水平决定人口增减，人口会从差的聚落迁往好的聚落。
- **雇工与生产链**：公司设施从附近聚落招工、按日发工资，工资越高越容易招到人，产量按在岗比例计算；所在维度没有聚落时照常满员生产。新增食品加工、林业、煤矿、纺织四个行业。
- **CPI 闭环**：央行议息使用消费篮子 CPI，加息 → 扩张放缓 → 供给 → 物价 → 再调息；物价偏离太多时央行还会直接平准消费品。
- **《金融周报》**：每周一期的实体报纸，到贸易站右键或在“更多操作 → 宏观行动”领取——头版大事、市场涨跌、民生、央行动态（议息、准备金率、平准）、你的生意，外加一条（可能已过时的）商机；饥荒这类大事会出号外。想要最新情报可以花钱做商情调查（“更多操作 → 财报商情”或 `/macro radar`）。
- **看得见的经济**：村子过得好冒开心粒子，挨饿时冒愤怒粒子，村民会在你经过时抱怨最缺的东西；缺人或缺设备的工厂冒烟；商队到货时放烟花敲钟；饥荒会全服公告。只影响表现，可在配置里关闭。
- **经济成就**：进度挂在原有进度树上——第一位员工、良心老板、新兴城镇、黄金时代、饥荒救援、商路大亨、垄断者、踩准议息、降准受益者、物价稳定，以及几个隐藏成就（血汗工厂、囤积居奇、通胀失控、割肉离场）。达成时不在线会在下次上线补发。
- 金融终端（高级模式）的“宏观”页签可查看总览、中央银行概况和各聚落民生与市场。

## GUI 操作

Minecraft-first 模式默认通过世界中的金融终端分流功能：市场终端负责商品行情和订单，仓储控制器负责实物存取与采购合同，银行柜台、公司办公桌、证券终端和中央银行控制台分别提供对应业务。随身金融账本用于查看余额和近期流水；管理员仍可使用完整金融界面进行维护。

兼容模式下也可以通过以下方式打开旧金融中心 GUI：

- `/market gui`
- `/finance gui`
- 默认快捷键 `F`

普通玩家可见以下标签页，管理员可见额外的仪表盘和管理标签页。

| 标签页 | 功能 |
| --- | --- |
| 行情 | 查看国际市场行情，选择商品并进行国际市场买卖；点击“K线”查看 30/60/120 天 OHLCV |
| 交易 | 创建 P2P 商品买单/卖单 |
| 订单 | 查看、吃单或取消商品市场挂单 |
| 库存 | 查看余额、虚拟商品库存和背包数量，进行存入/取出 |
| 公司 | 创建公司、管理自己的公司、查看最新财报与破产风险、发起 IPO；上市后可发起增发融资和股东提案投票 |
| 股票 | 查看上市股票、K 线和均线，下单交易、查看持仓，设置和取消止盈/止损条件委托，并认购增发股票 |
| 记录 | 查看自己的交易记录；管理员可查看全部记录 |
| 资产 | 查看现金、商品、股票、公司债和央行票据价值，以及总资产、今日盈亏和资产占比 |
| 提醒 | 为商品或股票设置涨到/跌到目标价提醒，并查看或取消自己的提醒 |
| 金融 | 在“指数/发行/债市/持仓/票据/贷款/期货/银行/基金/保险/区域”子页中管理固定收益、贷款、银行业务、商品期货、基金、保险，并查看区域风险行情 |
| 宏观 | 宏观经济总览、中央银行概况、聚落民生与市场（高级模式） |
| 仪表 | 管理员查看货币总量、成交量、价格指数、破产风险和央行最近干预 |
| 管理 | 管理员添加/删除商品 |

管理员商品管理页支持：

- 从手中添加：识别手持物品并添加为商品。
- 常用物品：按分类快速添加常见 Minecraft 物品。
- 已注册商品：查看和删除已注册商品。
- 价格历史：清理商品、股票或全部价格历史快照；只影响趋势图历史，不修改当前价格。
- 分红设置：调整全局分红比例和分红周期。

管理员“仪表”页展示货币总量、玩家可用/冻结资金、公司现金、NPC 市场资金、央行储备、当日商品与股票成交量、价格指数、风险公司数量和最近 30 个 MC 日趋势。商品和股票成交量只在结算成功后计入指标；撤单、被拒绝的下单和读取历史记录不会增加成交量。

## 游戏内循环

| 间隔 | 内容 |
| --- | --- |
| 每个 MC 天，24000 tick | 保存上一日指标后重置日内统计；触发事件、公司生产和交易、国际市场补货/消耗、央行检查、公司利润结算与财报生成、股票基本面更新、分红检查、融资项目到期结算、股东提案结算和破产风险检查；NPC 做市与 NPC 投资者调仓、村民采购、商队发车、银行恐慌度、财报季，以及宏观经济的人口消费、雇工、本地价格、财政和周报 |
| 每 3 分钟，3600 tick | 商品和股票刷新噪声、衰减动量、重算价格，并检查股票条件委托和价格提醒 |
| 每 1 分钟，1200 tick | 商品和股票衰减动量、重算价格，并检查股票条件委托和价格提醒 |

游戏内经济周期使用世界持久化时间 `overworld().getGameTime()` 计算 MC 天数，因此服务器重启不会重置融资期限、投票截止、分红周期或破产倒计时，也不会重复结算。

## 服务器配置

首次启动后 Forge 会生成 `config/finance-common.toml`，服主可以调整经济平衡参数，不必重新编译模组。主要分组包括：

- 玩法：玩家驱动生产、旧式自动生产兜底比例。
- 金融产品：基准利率、债券/贷款上限与期限、信用等级分数线。
- 公司与股票：默认分红比例与周期、破产风险天数和现金安全线、股东提案最低参与率、做市商价差、IPO 费用、提醒与条件委托上限。
- NPC 投资者：`npcInvestorsEnabled`、`npcVotingEnabled`、初始资本、每日预算、资金池底线、持股与日成交量上限、各原型接受要约的溢价。
- 宏观经济（`macroEconomy`）：总开关、雇工、世界反馈 `worldFeedback`、周报等。
- 中央银行（`centralBank`）：物价目标与容忍区间、准备金率自动调整与上下限、公开市场操作开关与每日上限、商品平准开关与价格区间。

部分默认项示例：

```toml
[gameplay]
playerDrivenCompanyProduction = true
allowLegacyAutomaticCompanyProduction = true
newCompaniesPlayerDrivenOnly = false
hybridLegacyFallbackRatio = 0.25

[financialProducts]
defaultBenchmarkRateBasisPoints = 500 # 5.00%
maxCorporateBonds = 256
maxCompanyLoans = 256
loanGraceDays = 3
indexBasePoints = 1000
annualMcDays = 365
maxBondTermDays = 3650
maxBondFinancingRatio = 0.8
maxLoanTermDays = 3650
maxContractRateBasisPoints = 10000
mediumDefaultRatePercent = 5.0
highDefaultRatePercent = 20.0
creditAaaMinimumScore = 90
creditAaMinimumScore = 80
creditAMinimumScore = 70
creditBbbMinimumScore = 60
creditBbMinimumScore = 45
creditBMinimumScore = 30
```

所有金融参数都有服务端上下界；客户端输入不能突破配置限制。为避免运行中的已发行合约被改写，修改公共配置后应完整重启服务器；基准利率的游戏内调整只作用于之后创建的债券和贷款，不追溯已有合约。

三套预设（Minecraft 优先、休闲协作服、传统金融）见 [docs/CONFIG_PRESETS.md](docs/CONFIG_PRESETS.md)，详细中文说明和默认配置示例见 [docs/CONFIG_ZH.md](docs/CONFIG_ZH.md)。

## 数据存储

数据保存在世界存档 NBT 中，服务器重启后会恢复。当前存档 `DataVersion = 39`，网络协议版本为 17；客户端与服务端需使用同一版本的模组。

| 数据名 | 内容 |
| --- | --- |
| `finance_data` | 账户、交易记录、订单、行情、事件、公司、股票、仓库等级、资本项目、采购合同、运单、聚落、公共需求、贡献与调查任务、区域指标、库存质押、经营对冲、运输托管引用、NPC 投资者、宏观经济与中央银行等金融状态 |
| `finance_inventory` | 玩家和系统账户的虚拟商品库存 |

加载世界数据时，模组会先清空内存中的静态经济状态，再从当前世界存档恢复，避免连续切换世界时出现跨世界数据残留。涉及冻结资产的坏记录会隔离或保留 reservation，而不是猜测归属或静默解冻。存档兼容策略见 [docs/SAVE_COMPATIBILITY_POLICY.md](docs/SAVE_COMPATIBILITY_POLICY.md)。
