# 存档兼容政策

## 基本规则

- 已有 NBT key 不重命名；确需改变时同时保留旧 key 读取和明确迁移。
- `EconomySavedData.DATA_VERSION` 只在持久化格式实际变化时递增。
- 新字段必须有安全默认值；单条坏记录应被隔离，不能使整个经济存档加载失败。
- 新入口配置只改变玩家如何访问功能，不改变既有资产、合同或日结语义。

## Minecraft-first 兼容

- 现有 `CommodityInventoryManager` 数量被定义为历史市场托管资产，不清零、不强制搬迁。
- 未来启用仓库容量后，超过容量的历史资产允许取出和结算，但在恢复到容量以内前不得继续存入。
- 旧公司默认保留原自动经营模式；新公司才可按配置默认采用玩家参与模式。
- 关闭新合同、仓库或高级入口，只能拒绝新业务，不能阻止退款、到期、撤单、付息、分红和破产清算。

## 新数据域

仓库使用 `Warehouses` 根节点（版本 1），保存世界级仓库身份、位置、所有者、容量、状态、权限和有界幂等键，不保存商品数量。

合同使用 `FinanceContracts` 根节点（版本 1），保存合同状态、商品、数量、奖励、期限、接受者、目标仓库、escrow 引用、有界幂等键和每日生成 key。加载顺序先恢复账户与商品，再恢复仓库和合同，以便验证 escrow 和商品引用。

旧存档缺少两个根节点时按空记录加载，不创建资产、不迁移旧托管。仓库已用量超过新容量只形成 `OVER_CAPACITY` 状态。单条损坏记录被隔离；资金归属无法权威确认时不自动转账。

公司世界玩法使用 `CompanyGameplay` 根节点（版本 1），在公司和仓库恢复后、合同恢复前加载经营模式、成员/邀请、公司仓库、办公桌、设施、每日标记和有界操作键。缺少该节点的旧公司只建立 `LEGACY_AUTOMATIC` 档案，不移动公司现金或旧库存；损坏成员、邀请或设施逐条跳过。公司删除后设施标记为 `ORPHANED`，不摧毁世界方块或清空仓库商品。

世界反馈使用 `WorldEconomyFeedback` 根节点（版本 1），只保存广播冷却、每玩家最多 32 条待领取通知和最多 4096 个稀疏终端位置；不保存客户端渲染状态。坏通知、非法维度和未知入口会逐条跳过。市场机会是可重建缓存，不写入存档。

物流使用 `Logistics` 根节点保存运单、令牌引用和有界幂等键；权威运输商品存放在独立运输 custody，不由货箱 NBT 声明。聚落使用 `Settlements` 根节点保存稳定身份、贡献和公共需求。探索使用 `Exploration` 根节点保存单个玩家目标、期限、冷却与 escrow 引用。缺少任一新节点按空数据加载，不创建资金。

阶段 0/1 没有新增持久化字段；阶段 2 加入仓库与合同后为 27；阶段 3 加入公司玩法域后为 28；阶段 4 加入世界反馈域后为 29；设施等级为 30；物流为 31；聚落为 32；探索为当前 `DATA_VERSION = 33`。

历史版本矩阵自动覆盖 13、15、17、19～33 的直接升级与重复加载。真实旧世界副本仍需人工核对业务含义，尤其是股票、债务、基金、期货、保险和 legacy 公司；夹具不能证明玩家主观预期。
