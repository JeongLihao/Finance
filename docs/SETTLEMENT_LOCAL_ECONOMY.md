# 聚落与本地经济

当前实现采用“现有村民 + 公共贸易站”方案，不注册新村民职业，也不修改原版寻路、工作日程或补货逻辑。聚落只在玩家放置并使用贸易站时登记，不扫描全世界村民或 POI。

## 数据与生命周期

- `SettlementRecord`：UUID、维度、贸易站锚点、状态、每日生成标记、袭击/伤亡事件键以及每玩家贡献摘要。
- `LocalDemand`：聚落、商品、主题、数量、奖励、独立 escrow、期限、接受玩家、状态和有界操作键。
- 活跃贸易站 UUID 被复制到远处时会分配新聚落身份；原位置或 16 格内停用锚点才能恢复旧身份。
- 拆除贸易站只将聚落设为 `DISABLED`，不会删除活跃需求、奖励 escrow、贡献或聚落商品托管。
- 存档子根为 `Settlements`，版本 1；全局 `DataVersion=32`。坏 UUID、超长名称、无商品引用和 escrow 不一致会被隔离，并只暂停聚落模块。

## 需求生成与预算

| 主题 | 默认商品 | 数量 | 触发 |
| --- | --- | ---: | --- |
| 食物 | 小麦 | 16～32 | 普通低频轮换 |
| 材料/库存 | 石头、铁或小麦 | 16～32 | 普通低频轮换 |
| 防御 | 铁锭 | 16～32 | 原版袭击存在 |
| 重建 | 石头 | 16～32 | 袭击结束或同日累计 3 名村民/铁傀儡损失 |

每个聚落每 MC 日最多尝试生成一项需求，且未结束需求默认不超过 8 项。奖励按可信市场 ask 价乘数量，再乘服务器配置的基点比例；创建前必须从现有 NPC 市场账户转入需求独立 escrow。预算不足、商品没有有效 ID 或上限已满时不创建任务，不读取玩家背包来定制奖励。

## 玩家流程

1. 在村庄附近放置并右键聚落贸易站。
2. 在最多 8 条公共需求中选择并接受；每玩家默认最多同时接受 4 条。
3. 把无 NBT、未损坏的真实 Minecraft 物品放入主背包，回到同一个贸易站点击“背包交付”。
4. 服务端预检距离、贸易站身份、期限、操作键、物品、聚落托管容量和玩家收款容量。
5. 实物进入聚落托管，escrow 原子支付玩家；任一环节失败则回滚物品和托管。

普通客户端只收到公共需求、任务标价、自己的已接受任务和自己的贡献，不收到 NPC 总预算、其他玩家任务或全量 escrow。

## 贡献、事件和性能

- 每次普通交付增加 10 点，重建交付增加 25 点；单次增量不超过 50，总点数上限 500，对应 0～5 级。
- 贡献只解锁关系表达和后续扩展空间，不修改利率、股票或全服商品价格。
- 每日只按最多 256 个已登记聚落查询其锚点处的原版 Raid 状态；不遍历村民、不强加载区块。
- 村民/铁傀儡死亡使用事件驱动的每日有界计数，前三次才改变一次聚落状态，不逐死亡广播。
- 上限：256 聚落、4096 需求、1024 条无 escrow 的终态历史、每聚落 256 名贡献者。

## 仍需真人验收

- 两名真实玩家在自然村庄完成接取和交付，核对 GUI Scale 2/3/4、钟声、粒子和状态贴图。
- 在真实袭击开始/结束后观察红色警戒、重建需求和服务器重启连续性。
- 用玩家仓库/密封货箱完成一段物流后再帮助村庄，核对“村庄物流伙伴”进度。
